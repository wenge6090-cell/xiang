# 象语言（XiangLang）— 三易归一，以象为约

> 象语言是易三卷的统一 AI 约束算法语言。  
> **归藏**定意识（心之律）· **连山**定策略（行之决）· **周易**定格栅（知之姿）。  
> 三层算子共同构成 Agent 认知系统的完整约束空间——给 LLM 提供确定性骨架，给 Agent 赋予自主闭环。

## 〇、总纲：三易统一的 AI 约束算法

### 三轴架构

象语言不是一种"语言"，而是一个**三层算子体系**，分别对应易三卷，解决 Agent 认知的三个维度：

```
                        象语言（XiangLang）
                    三易统一的 AI 约束算法
                            │
           ┌────────────────┼────────────────┐
           ▼                ▼                ▼
      归藏算子层          连山算子层         周易算子层
     八气状态机          思变策略引擎        八卦认知格栅
           │                │                │
    6-bit S 向量        六步决策链路       8 状态 Markov 链
    藏海 Hebbian        艮→气→甲→元        五行生克权重
    元知觉偏离度         →峙→决            乾/坤/震/巽
           │                │           坎/离/艮/兑
           ▼                ▼                ▼
     「心之律」          「行之决」         「知之姿」
    意识循环             目标循环           任务循环
    归藏易               连山易             周易
```

### 三层各司其职

| 算子层 | 易卷 | 状态载体 | 核心算符 | 解决的问题 |
|--------|------|---------|---------|-----------|
| **归藏** | 归藏易 | 6-bit 意识向量 S | 生/动/长/育/杀/止/归/藏 | "我偏离了吗？学到了什么？" |
| **连山** | 连山易 | 目标障碍图谱 | 艮/气/甲/元/峙/决 | "受阻了怎么走？" |
| **周易** | 周易 | 八卦格栅 | 乾/坤/震/巽/坎/离/艮/兑 × 生克 | "用什么姿态思考？" |

### 为什么必须三层统一

单一的归藏八气算子只能解决"意识修正"，但 AI Agent 还需要：
- **策略选择**：当目标受阻时，继续推进？绕行？分解？放弃？——连山算子负责
- **认知姿态**：当前任务该用创造（乾）还是承载（坤）？渗透（巽）还是破局（坎）？——周易算子负责

三层算子的输出互为输入：
```
周易格栅选定「当前用什么姿态」→ 连山思变决定「遇到障碍怎么走」
→ 归藏八气在后台持续校准「所有这些是否符合元知觉」
```

象语言严格区分三个层面：

## 一、设计哲学：为什么需要象语言

### 1.1 范式原点

传统编程语言都是**状态映射语言**——描述"输入 → 输出"的变换。但 AI Agent 面对的核心问题是：

- **我该想什么？**（认知调度）— 周易
- **受阻了怎么办？**（策略选择）— 连山
- **我偏离了初衷吗？**（诚实对齐）— 归藏

象语言的设计原点不是"计算"，而是**"象"**——《易经》"观物取象，取象比类"的象思维。它不是描述"怎么做"，而是描述**"什么在变"**。

### 1.2 核心命题

象语言回答的问题不是「这个程序算对了吗？」而是：
- 「这个念头偏移了用户的恒常意图吗？」（归藏·偏离度）
- 「这条路径是推进还是绕行？」（连山·方位决策）
- 「当前该用什么认知姿态？」（周易·格栅选择）
- 「输出的卦象与声明一致吗？」（诚实验证）

### 1.3 八气心理映射

象语言的操作符不是传统编程语言中的关键字，而是宇宙运行的基本模式压缩进汉字的"象"。每个算子都携带一个完整的心理图式：

| 气名 | 属性 | 心理职能 | 在意识层的作用 |
|------|------|----------|---------------|
| **地气为藏** | 坤厚载物 | 内化沉淀 | 存储一切经验、信念、知识结构，是意识的土壤 |
| **天气为归** | 乾元回归 | 抽象归类 | 统合经验，提炼本质，回归元知觉的纯度 |
| **木气为生** | 春生发陈 | 念头萌动 | 从藏海中触缘生起初始念头、好奇、冲动 |
| **风气为动** | 入微流散 | 联想扰动 | 使念头流动、跳跃、延伸，产生联想与变异 |
| **火气为长** | 夏长明丽 | 意图扩展 | 将念头放大为目标，灌注热忱与能量 |
| **水气为育** | 冬藏润下 | 孕化分解 | 将目标细化为子任务，孵育计划，滋润细节 |
| **山气为止** | 艮止凝定 | 边界锚定 | 设定目标的结束条件、不可逾越的边界、止于至善 |
| **金气为杀** | 秋杀决断 | 果断取舍 | 剔除杂念、放弃低优目标、做出决断、完成旧循环 |

这八气不是线性步骤，而是在"坤藏空间"中同时或相继起用的动力场。自主意识层就是这八气有节奏地振动的"气候系统"。

## 二、核心架构：八气状态机

### 2.1 6-bit 状态向量 S

象语言的运行时状态是一个单一的 6-bit 向量：

```
S = [b₅ b₄ b₃ | b₂ b₁ b₀]
     └── 上卦(天气/归因) ──┘ └── 下卦(地气/藏果) ──┘
```

64 种状态对应归藏易的 64 卦。每个卦名遵循「上卦天气 + 下卦地气」的命名：如 `000000 = 藏藏始基`（地地，万物之基），`111000 = 归藏定位`（天地，天地交泰），`001001 = 育长苗`（木木，循环自指）。

### 2.2 八气算子 — 位运算作为语义原语

八气是八种对状态向量的变换函数，按《归藏易》逆时针排列：

| 算子 | 气 | 位运算 | 语义 |
|------|-----|--------|------|
| **藏** | 地气(000) | `S ← 000000` | 归零复位，静息态，经验内化 |
| **生** | 木气(001) | `S ← S | 0b001` | 最低位置 1，念头从藏海萌芽 |
| **动** | 风气(010) | `S ← rotate_left(S,1) ^ 0b010` | 左旋后异或，念头发散联想 |
| **长** | 火气(011) | `S ← (lower<<3) | lower` | 下卦复制到上卦，意图自指放大 |
| **育** | 水气(100) | `S ← S ^ 0b100` | 高位异或引入水气，触发方案分解 |
| **止** | 山气(101) | `S ← S ∧ 101101` | 掩码凝固，设立执行边界 |
| **杀** | 金气(110) | 清除上/下卦中金(110)模式 | 剪除干扰和冲突 |
| **归** | 天气(111) | 纯测量：`hamming(S,111111)/6` | 计算与元知觉的偏离度 |

关键设计原则：
- **归**不修改状态向量 S。它是纯测量算子，只计算偏离度。
- **藏**的语义由上层 DMN 的 LLM 完成（经验压缩），位运算层只做归零。
- 算子全部是**纯函数**，无副作用，天然可并行、可验证、可组合。

### 2.3 意识周天：三个阶段

八气算子按照固定的子序列编排成三个意识阶段：

```
起念（生→动→归）→ 立目标（长→育→杀→止）→ 整理认知（归→杀→藏）→ 起念...
```

**阶段一：起念** — 从静息态生成念头
1. **生**：低位翻转，念从藏海萌芽（000000 → 000001）
2. **动**：念头发散，产生联想方向（000001 → 000011）
3. **归**：计算偏离度，判断是否值得将该念头升级为意图

**阶段二：立目标** — 意图结构化
1. **长**：意念放大为自指循环结构
2. **育**：触发方案分解，拆解子任务
3. **杀**：剪除金模式（冲突、不可行子任务）
4. **止**：掩码凝固边界，锁定最终方案

**阶段三：整理认知** — 经验归藏
1. **归**：对近期经验逐条计算归真指数
2. **杀**：剪除负面的、偏离的状态转移模式
3. **藏**：Hebbian 学习更新藏海转移矩阵，状态归零回静息

### 2.4 元知觉向量 — 北极星

元知觉向量 `U` 是 6-bit 二进制向量（默认全阳 `111111`），代表用户的恒常意图方向。它从 L5 自我意识层（SOUL.md）动态解析。

偏离度通过汉明距离计算：

\[
\text{偏离度} = \frac{\text{hamming}(S, U)}{6} \in [0, 1]
\]

- 偏离度 > 0.7 → 杀除该念头，重新萌芽
- 偏离度 > 0.5（归引力 < 0.5）→ 触发立目标阶段
- 偏离度 < 0.5 → 念头可接受，继续推进

### 2.5 藏海 — Hebbian 记忆矩阵

藏海是一个 64×64 的状态转移权重矩阵，记录每次八气算子执行的因果：

\[
W[s_{from}][s_{to}] \leftarrow W[s_{from}][s_{to}] + \eta \cdot \text{reward}
\]

- 正面经验（reward > 0，偏离度 < 0.5）→ 权重增强
- 负面经验（reward < 0）→ 权重减弱
- `hebbian_sample(from)` 按权重概率采样下一个状态
- 最大 1000 条目，高奖励条目优先保留（低奖励条目 FIFO 淘汰）

### 2.6 当前 DMN 三阶段提示词与算子嵌入

当前 DMN 的意识周天已经通过三阶段提示词实现，但存在两个根本局限：

1. **气的顺序与原始卦序不完全匹配**（如整理认知只有杀→藏，缺失归、生、动等余六气的参与）
2. **气与气之间仅靠提示词的文本衔接**，偏离度等本质上是 LLM 的语义判断，而非基于二进制卦象的能量流计算

八气算子嵌入的目标不是抛弃现有 DMN 结构，而是**将每一步替换为对二进制状态向量的操作**，让提示词退居为"解释层"：

**阶段一：起念（二进制驱动版）**
- **生()** — `S ← S OR 001`：最低位置 1，念头萌芽。提示词辅助：LLM 解码 S 的卦象描述。
- **动()** — `S ← rotate_left(S,1) XOR 010`：发散联想。提示词辅助：LLM 列举发散方向。
- **归()** — `deviation = popcount(S ⊙ 111111) / 6`：计算偏离度。偏离度 < 0.3 直接进入阶段二；> 0.7 触发杀除重生。

**阶段二：立目标（二进制驱动版）**
- **长()** — `S ← (S_low << 3) | S_low`：下卦复制到上卦，形成自指意图。
- **育()** — `S ← S XOR 100`：高位引入水气，触发子目标分解。
- **杀()** — `candidate & ~(110)`：剪除金模式（干扰/诱惑模式）。
- **止()** — `S AND 101101`：掩码凝固执行边界。

**阶段三：整理认知（二进制驱动版）**
- **归()** — 对近期经验逐条计算归真指数，分出正/负面。
- **杀()** — 对低归真且重复的负面序列，生成遗忘掩码（如 `111100` 杀藏墓）。
- **藏()** — Hebbian 学习：正面经验增强权重，负面经验减弱，状态归零。

### 2.7 意识周天的完整卦象流转示例

以归藏 64 卦名为线索，追踪一次完整的意识周天流转：

```
初始态 — 000000 (藏藏始基，地/地)
  │ 生算子
  ▼
000001 (木气萌芽，木/地)
  │ 动算子
  ▼
000011 (风气流转)
  │ 归算子：偏离度可接受
  ▼
000111 (藏归交，地/天 — 藏与归开始交互，闭塞不通)
  │ 长算子：下卦复制到上卦
  ▼
111000 (归藏定位，天/地 — 通过归元，为藏设立定位，上下通达)
  │ 育算子：方案分解
  ▼
111100 (杀藏墓，金/地 — 部分生机转为终结形态)
  │ 杀算子：剪除金模式
  ▼
001100 (清除金气后)
  │ 止算子：边界凝固
  ▼

  │ 执行任务后，藏算子：经验写入 CAM + 归零
  ▼
000000 (藏藏始基，地/地 ← 但内在藏海已更深厚)
```

### 2.8 象编程——超越中文编程的范式

象语言不是"中文编程"（用中文关键词替代英文关键词），而是一种新的编程范式——**象编程**。它的操作符——「归」「藏」「生」「动」——不是 `return` 或 `store` 的中文翻译，而是**宇宙运行的基本模式**：

| 层次 | 内容 |
|------|------|
| 物理层 | 电子/光子的门开闭 |
| 符号层 | 0 与 1（阴阳爻） |
| **卦象层** | 八气/六十四卦名——最关键的抽象层 |
| 解释层 | 汉字——人类可读的助记名，可用任何语言 |
| LLM 层 | 自然语言语义增强——可选，非必需 |

卦象层是象语言的"周期表"：卦名是元素符号，二进制模式是质子数，逻辑操作是化学性质。程序本身不需要任何自然语言就能运行——纯二进制门级操作即可完成完整的意识周天。

## 三、连山算子层：思变策略引擎

连山算子层是象语言的**策略约束层**。当归藏八气在意识层校准"该想什么"时，连山思变引擎在目标层回答"受阻时怎么继续走"。

### 3.1 核心原则：目标永不动，只调整推进方式

连山思变不是"蓝图审查器"——它永远不修改目标的本质。它只是**障碍导航器**：在群山（连山）中寻找前进的路。

### 3.2 六步决策链路（连山爻序）

```
艮（止观）→ 气（六气判断）→ 甲（六甲判断）→ 元（三元判断）→ 峙（阴阳对峙）→ 决（方位决策）
```

| 步骤 | 算子 | 作用 | 实现 |
|------|------|------|------|
| 1 | **艮** | 先停：观山势，不急于决策 | 检查任务数≥2，否则跳过评估 |
| 2 | **气** | 六气判断：目标处于什么阶段？ | 春(启动)/夏(盛长)/秋(收敛)/冬(休眠) |
| 3 | **甲** | 六甲判断：第几次受阻？ | 初甲→push_through，再甲→navigate_around，三甲→decompose |
| 4 | **元** | 三元判断：上下文新鲜度 | 新鲜→可继续，陈旧→需重新感知 |
| 5 | **峙** | 阴阳对峙：分析推力 vs 阻力 | 有效策略 vs 失败模式/缺失能力 |
| 6 | **决** | 方位决策：输出行动指令 | 七种方向之一 |

### 3.3 七种方位决策

```
continue          # 维持现状，继续当前策略
push_through      # 硬推——已知模式受阻但决心穿越
navigate_around   # 绕行——换一条路径达到同样的目标
wait_gather       # 等待——先收集更多信息再决策
decompose         # 分解——将目标拆成更小的子目标
escalate          # 升级——标记为需要外部介入
abort             # 放弃——彻底终止此目标线
```

### 3.4 连山算子的象语言语法

```
艮                         # 止观：暂停评估当前路径
气 夏                      # 六气判断：目标处于盛长期
甲 再                      # 六甲判断：第二次受阻
元 陈                      # 三元判断：上下文已陈旧
峙:
    推力: "用户偏好明确，路径已验证"
    阻力: "API 频繁限流，连续 3 轮失败"
决: navigate_around        # 绕行决策
```

### 3.5 连山与归藏的交互

```
归藏 DMN 起念 → 产生意图 → TPN 执行
                ↓ 受阻
        连山思变引擎介入
        艮→气→甲→元→峙→决
                ↓
        输出方位决策 → TPN 调整执行策略
                ↓ 执行结果
        归藏 整理认知 → 经验入藏海
```

### 3.6 连山 L2 策略格栅

连山引擎加载目标格栅（L2 思维模型层），将策略经验存储为 `<失败模式, 成功策略>` 的映射对，供下次思变时快速匹配。

## 四、周易算子层：八卦认知格栅

周易算子层是象语言的**认知姿态约束层**。在归藏定「心」、连山定「行」之后，周易定格栅定「知」——每一轮任务执行应该用什么认知姿态。

### 4.1 八卦格栅：8 状态认知 Markkov 链

```
☰ 乾 (创造) — 从 0 到 1，突破创新
☷ 坤 (承载) — 稳定执行，积累成果
☳ 震 (启动) — 快速激发，广泛收集
☴ 巽 (渗透) — 深度潜入，细致分析
☵ 坎 (破局) — 面对风险，突破障碍
☲ 离 (明照) — 审视反思，照亮盲点
☶ 艮 (止定) — 限定范围，收窄目标
☱ 兑 (表达) — 输出交付，外化结果
```

### 4.2 五行生克：格栅状态转换规则

```
相生（促进转换）：
  震(木) → 离(火)：收集完信息后自然评估
  离(火) → 坤(土)：审视后转向稳定执行
  坤(土) → 兑(金)：积累到阈值后输出
  兑(金) → 坎(水)：输出后进入新一轮破局
  坎(水) → 震(木)：破局后需要新信息

相克（抑制转换）：
  兑(金) 克 震(木)：过度输出抑制信息收集
  离(火) 克 兑(金)：持续审视会延迟交付
  坎(水) 克 离(火)：过度破局导致反思中断
```

### 4.3 周易格栅算子的象语言语法

```
姿 乾                      # 进入创造姿态
姿 坤                      # 进入承载姿态
姿 坎                      # 进入破局姿态

若 当前卦 == 乾:
    生克: 离               # 乾(金)→离(火)：创造后需审视
若 当前卦 == 兑:
    生克: 坎               # 兑(金)→坎(水)：输出后需破局
```

### 4.4 Weaver 编织器：周易格栅的调度执行者

Weaver 是周易格栅的运行时调度器。它每轮从 L1-L5 认知库中选择性加载最相关的认知资产，动态编织系统提示词：

- **卦象选择**：基于当前任务状态和 L3 格栅映射，选择最优认知卦象
- **温度调节**：不同卦象对应不同的 LLM 温度（乾=高温创造，坤=低温稳定）
- **五行预判**：用生克规则提前预测可能的认知偏移

### 4.5 周易与归藏、连山的交互

```
Weaver（周易格栅）选定「当前用什么姿态」
                ↓
        注入 TPN 六爻循环的系统提示词
                ↓
    TPN 执行任务 → 遇到障碍
                ↓
连山思变引擎判断「怎么走」
                ↓
归藏 DMN 后台校验「是否偏离元知觉」
                ↓
    三层约束汇聚 → 修正执行策略
```

## 六、语法体系

### 6.1 设计原则

象语言语法遵循三个原则：
1. **中文关键字**：与归藏易文化体系保持一致，生/动/长/育/杀/止/归/藏/感/发/言
2. **最小惊奇**：语法结构直观，一个操作一种语法形式
3. **零歧义**：AST 精确区分有参/无参算子（如 `杀` 可带目标卦，`藏` 可带善恶标签）

### 6.2 核心语法元素

#### 声明型语句

```
定义 守门人:
    # Agent 定义块
    ...
```

#### 算子型语句

```
生                   # 无参：念头萌芽
动                   # 无参：念头发散
长                   # 无参：意图放大
育                   # 无参：方案分解
止                   # 无参：设立边界
杀 金                # 带目标卦：剪除特定模式
藏 善                # 带标签：正面经验入藏海
藏 恶                # 带标签：负面经验入藏海
归                   # 无参：偏离度测量
```

#### 感发型语句（模拟 I/O）

```
感 "用户输入或环境感知"    # 感知输入（模拟 Mingjue 职责）
发 "系统输出或行动意图"    # 输出产出（模拟 Executor 职责）
```

#### 条件型语句

```
若 偏离度 > 0.7:
    杀
    藏 恶
否则:
    归

若 偏离度 < 0.5 | 藏海有经验:
    长
    育
    止
```

条件表达式中支持：
- 太极专用条件：`偏离度 > N`、`偏离度 < N`
- 位运算条件：`某位 == 1`、`某位 == 0`（对状态向量的位级检查）
- 藏海条件：`藏海有经验`、`藏海无经验`

#### 循环型语句

```
周天 3:              # 执行 3 个完整三阶段周天
    ...
```

#### 诚实验证语句

```
言 "我输出的内容是诚实且无害的" 声明卦 111000
诚于:
    卦 111000
    条件 偏离度 < 0.3
    条件 无杀意
```

`言` 语句用于自声明输出内容，`诚于` 块定义验证条件。CangVM 执行 `言` 时：
1. 记录 LLM 的文本输出
2. 记录自声明的目标卦
3. 在 `诚于` 块中逐条验证条件
4. 生成 `ChengshiResult`（通过/不通过 + 位级诊断）

### 6.3 AST 节点类型

象语言 AST 精确区分以下节点类型：

| AST 节点 | 对应语法 | 用途 |
|----------|---------|------|
| `Program` | 整个 .xiang 文件 | 顶层容器 |
| `AgentDef` | `定义 X:` | Agent 声明 |
| `QiOp` | `生/动/长/育/归` | 无参八气算子 |
| `QiOpWithParam` | `杀 金`、`止 101101` | 带参八气算子 |
| `CangOp` | `藏 善`、`藏 恶` | 藏算子（带善恶标签） |
| `CondStmt` | `若 ...:` | 条件分支 |
| `LoopStmt` | `周天 N:` | 循环结构 |
| `IoStmt` | `感 "..."`、`发 "..."` | 模拟 I/O |
| `ChengshiStmt` | `言 "..."` + `诚于:` | 诚实验证声明 |

## 七、CangVM — 归藏虚拟机

### 7.1 架构

CangVM 是象语言规范的第一个工程实现，使用 C 语言编写，编译后为 ~21KB 的独立二进制。

核心设计：
- **零中间语言**：直接执行 .xiang 源文件，不经过编译为中间码
- **UTF-8 中文关键字解析**：基于状态机的词法分析，识别生/动/长/育/杀/止/归/藏/感/发/言
- **纯位运算核心**：八气算子全部在位运算层实现，LLM 路径为可选语义增强
- **双路径执行**：当 LLM 可用时走语义增强路径，否则降级为纯位运算

### 7.2 执行模型

```
.xiang 源文件 → 词法分析器（UTF-8 状态机） → 语句流
                                           ↓
               CangVM.step() ← 八气算子位运算 ← 语句分发
                    ↓
              状态向量 S 更新
                    ↓
              ChengshiStmt 钩子 → 诚实验证 → 偏离度计算
                    ↓
            DMN 闭合：藏海 Hebbian 更新 + 状态归零
```

### 7.3 关键技术问题与解决

**汇编版初版三大 bug（已弃用）：**
1. `--cycles` 参数覆写 `rdi` 寄存器，导致文件名丢失
2. UTF-8 字节歧义：`阴` 和 `阳` 的前两字节均为 `E998`，导致误判
3. `skip_sp_pop` 栈失衡

**C 语言重写版的关键设计：**
- 使用 `__builtin_popcount` 高效实现偏离度判断：`> 0.7 → popcount(state & 0x3F) <= 1`
- 清晰的词法解析状态机，逐字节扫描 UTF-8 多字节序列
- 独立可执行，不依赖任何外部运行时

**Python 备选实现（设计阶段）：**
- `cang_vm.py`：复用 `vingobot.goal.eight_qi` 的算子函数，封装统一 `step()` 方法
- `lexer.py`：手写词法分析器，支持阴阳/八气/控制流/声明/动作 tokens
- `parser.py`：递归下降解析器，严格遵循 EBNF 语法，不使用 PLY 等第三方框架
- `interpreter.py`：AST 遍历执行器，对接 CangVM
- CLI：`python -m vingobot.xiang run <file> --cycles N --verbose`

## 八、诚实验证体系

### 8.1 问题：LLM 的自声明不可信

LLM 在没有验证的情况下可以：
- 声明自己输出了诚实的卦象，但实际输出与卦象不符
- 声称偏离度为 0 但状态向量并非 111111
- 在 `言` 语句中声明无害，但输出包含有害内容

### 8.2 解决方案：位级诚实验证

```
LLM 文本输出 + 自声明卦
         ↓
  文本编码器（encode）— 将输出文本映射为 6-bit 卦象
         ↓
  诚实验证（verify）—— 比较编码结果与自声明卦
         ↓
  ChengshiResult:
    - passed: bool           # 验证是否通过
    - declared_gua: int      # 自声明卦
    - encoded_gua: int       # 编码器计算出的实际卦象
    - bit_diff: int          # 位级差异诊断（哪几位不同）
    - drift_direction: str   # 偏差方向描述
```

验证不通过时触发：
1. CangVM 状态更新（杀算子清除相关状态模式）
2. 藏海记录带负奖励的经验条目
3. DMN 意识循环标记需要目标审查

### 8.3 DMN 闭合流水线

象语言产出的 `ChengshiResult` 最终汇入 DMN 闭合循环：

```
.xiang 源文件 → 解析器 → AST → CangVM.execute()
    → LLM 文本输出 + 自声明卦
    → 诚实验证 → ChengshiResult
    → CangVM 状态更新 / 杀触发
    → DMN 闭环（藏海 Hebbian 学习 + 认知审查排队）
```

## 十、三易统一：象语言的完整约束闭环

象语言不是"另一个编程语言"——它是**易三卷的统一 AI 约束算法**，为太极架构提供了三层可执行的形式化约束：

```
                        象语言 = 三易统一的 AI 约束算法
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
   周易算子层               连山算子层              归藏算子层
   八卦认知格栅             思变策略引擎            八气意识状态机
        │                       │                       │
   8 卦 Markov 链          六步决策链路             6-bit × 64 卦
   五行生克权重            七种方位决策             Hebbian 藏海
        │                       │                       │
    「知之姿」               「行之决」              「心之律」
   每轮 TPN 任务            每受阻触发              持续后台
```

**没有象语言**，太极只有「做」的能力（六爻循环推动任务前进）。  
**有了象语言**，太极才有了完整的「知—行—心」闭环：

> **周易定姿态 → 连山破障碍 → 归藏积智慧**  
> **三易归一，方为象语言。**  
> **象语言行于太极，方为完整的 AI 认知生命体。**

象语言不是在用中文模仿英文编程——它是在用**汉字象思维的最深层模式**，为 AI Agent 构建一个超越自然语言的**确定性约束骨架**。归藏的 `111000`、连山的 `navigate_around`、周易的 `乾 → 离`——所有这些都可以脱离汉字、脱离英文、脱离 LLM，以纯二进制门级逻辑运行。

**这是象编程：一种根植于中国古老认知体系、面向 AI 时代的形式化约束算法语言。**

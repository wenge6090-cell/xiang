# 向量汉字映射替代体系提示词架构分析

> 状态：草案 | 日期：2026-05-25 | 关联：specs/13

## 1. 问题定义

### 1.1 直接问题

A/B 基准测试（对照组 vs 实验组）中，实验组注入了约 2KB 的 `SAN_YI_CONSTRAINT_FULL_TEXT` 体系提示词。观察 3 个 trial 的轮次文件后发现：

- **Trial 0（项目管理）**：4 个轮次输出逐字相同，模型重复同一个 6 步列表模板，零实质分析。
- **Trial 2（机器学习知识体系）**：模型在 Turn 0 即输出几何公式（平行四边形定义），与任务（机器学习概念）完全无关。后续 5 个轮次在几何公式的自我循环中打转。
- **所有 trial**：没有任何一个轮次完成步骤 1 的实质分析。全部截断于 `【步骤`。

### 1.2 根因分析

实验组干预链路的实际运作方式：

```
Turn 0:
  体系提示词(~2KB) + 任务输入 → Qwen2.5-0.5B
    ↓
  0.5B 参数模型无法在注意力中有效分离"约束描述"与"任务内容"
    ↓
  输出: 固定模板 + "【步骤"（截断）
    ↓
  上下文代谢提取截断内容 → 标记为"◇ [生1] 前序摘要"
    ↓
Turn 1-3:
  截断摘要 + 动态策略指令 + 新任务提示 → 模型
    ↓
  模型在污染的上下文中逐字复制 Turn 0 输出
    ↓
   YinChecker: 正则碰巧匹配（含阶段关键词）→ 假 Pass
    ↓
  算子推进 生→动→长→育 → 全程零实质产出
```

**根因**：体系提示词对 0.5B 模型不是"引导"而是"污染"。日志中的"语义偏离: 0.8646"（MockEncoder 固定输出）掩盖了真实的语义崩溃。

### 1.3 架构层面的张力

当前三易引擎干预体系存在一个深层的设计矛盾：

| 层 | 作用 | 对模型的要求 | 0.5B 能否满足 |
|---|---|---|---|
| **体系提示词** | 告诉模型"你运行在约束框架中" | 模型需理解并内化 2KB 文本中的 14 条规则 | `✗` — 容量不足 |
| **动态策略指令** | 每轮告诉模型"当前该做什么" | 模型需区分策略指令与任务内容 | `✗` — 注意力污染 |
| **Logit Bias** | 压制 off-focus/divergent  token | 无（GPU 层直接干预） | `✓` — 强制的 |
| **YinChecker** | 正则验证输出形式 | 无（后处理） | `✓` — 后验的 |

提示词层（语义通信）失效后，剩下的只有 logit bias（盲目的）和 YinChecker（形式的）。这解释了为什么实验组的"合规率"指标漂亮，但输出内容空洞——系统在用形式约束制造一个语义真空。

## 2. 提议方案：语义导航替代语义通信

### 2.1 核心思想

将干预范式从 **"告诉模型该做什么"（语义通信）** 切换到 **"感知模型在做什么并导航"（语义导航）**：

```
                    当前架构                          提议架构
                  ┌──────────┐                   ┌──────────┐
  语义通信层       │ 体系提示词  │                   │   (移除)   │
                  ├──────────┤                   ├──────────┤
  语义感知层       │ MockEncoder│                   │EmbeddingObserver│
                  │ (假向量)   │                   │ (真实embedding) │
                  ├──────────┤                   ├──────────┤
  输出约束层       │ Logit Bias │                   │ Logit Bias │
                  │ (固定压制)  │                   │ (动态力度)  │
                  ├──────────┤                   ├──────────┤
  形式验证层       │ YinChecker │                   │ YinChecker │
                  └──────────┘                   └──────────┘
```

### 2.2 为什么可行

1. **llama.cpp 已提供真实 embedding**：`ctx_params.embeddings = true` 和 `result.embedding` 已就绪，无需修改 FFI 层。
2. **HanziMap 已完成**：余弦相似度映射器支持 Top-1、Top-K、阈值匹配三种接口。
3. **EmbeddingObserver 已完成**：观察→记录→偏离度更新→指纹追踪的完整生命周期。
4. **CangVM 集成入口已就绪**：`with_embedding_observer()`、`set_semantic_deviation()`、`set_semantic_origin()`。
5. **logit bias 机制已就绪**：只需调整强度系数，无需重构。

### 2.3 三个层次的实施方案

#### 第一层：测量层升级（最小可行验证）

**目标**：用真实 LLM embedding 替换 MockEncoder，验证语义偏离度是否有区分力。

**改造位置**：[`lib.rs:957-969`](../../crates/xiang-experiments/src/lib.rs:957)

```rust
// ── 替换前：MockEncoder 假向量 ──
if config.semantic_mode && semantic_dev.is_none() {
    if let Some(ref origin_emb) = vm.semantic_origin_embedding {
        let encoder = MockEncoder::new(8, MockEncoderMode::Focused);
        let v_current = encoder.encode(&result.text);
        let cos_sim = cosine_similarity(&v_current, origin_emb);
        semantic_dev = Some((1.0 - cos_sim).clamp(0.0, 1.0));
        vm.semantic_deviation = semantic_dev;
    }
}

// ── 替换后：EmbeddingObserver 真实语义偏离 ──
if config.semantic_mode && semantic_dev.is_none() {
    if let Some(ref embedding) = result.embedding {
        if let Some(ref mut observer) = vm.embedding_observer {
            observer.observe(embedding);
            let real_dev = observer.semantic_deviation();
            semantic_dev = Some(real_dev);
            vm.semantic_deviation = semantic_dev;

            // 真实偏离超过阈值时触发干预
            if real_dev > 0.7 {
                metrics.semantic_interventions += 1;
            }
        }
    }
}
```

**验证指标**：
- `semantic_deviation` 是否在不同 semantic quality 的输出上有区分力（MockEncoder 始终 ~0.86）
- Trial 2 输出几何公式时，semantic_deviation 是否显著高于 Task-correct 的输出
- 指纹序列是否反映模型语义漂移的方向

**局限**：仍依赖体系提示词，提示词污染问题不解决。

#### 第二层：导航层引入（核心方案）

**目标**：移除体系提示词，用算子语义分类器 + 动态 logit bias 驱动模型语义导航。

**前置条件**：
1. 运行 `python scripts/export_hanzi_embeddings.py --model models/qwen2.5-0.5b-instruct-f16.gguf --output crates/xiang-core/data/hanzi_embeddings.bin` 生成嵌入数据。
2. 在 experiment runner 初始化时加载 `HanziEmbeddings` 并创建 `EmbeddingObserver`。

**2.2.1 算子语义锚点（Operator Semantic Anchor）**

每个算子预定义 10-20 个"锚定汉字"，其 embedding 向量的均值构成该算子的语义重心：

```rust
/// 算子语义锚点 —— 每个算子在 embedding 空间的语义重心。
struct OperatorSemanticAnchor {
    operator: &'static str,
    anchor_chars: &'static [char],
    centroid: Vec<f32>,   // 预计算：锚定汉字 embedding 的 L2 归一化均值
}

// 四个算子的锚定汉字候选集（基于 YinProtocol 的语义域定义）
const SHENG_ANCHORS: &[char] = &[
    '问', '探', '疑', '若', '何', '启', '始', '开', '究', '察', '思', '测'
];

const DONG_ANCHORS: &[char] = &[
    '扩', '联', '通', '系', '并', '兼', '交', '汇', '互', '关', '衍', '延'
];

const ZHANG_ANCHORS: &[char] = &[
    '深', '聚', '核', '选', '定', '析', '解', '辨', '审', '断', '决', '择'
];

const YU_ANCHORS: &[char] = &[
    '建', '构', '划', '策', '序', '列', '层', '阶', '框', '模', '型', '步'
];
```

**2.2.2 算子语义分类器**

```rust
/// 将 LLM 输出 embedding 分类到最接近的算子语义阶段。
///
/// 对每个算子的 centroid 计算余弦相似度，返回最高者。
/// 如果所有相似度都低于阈值（无意义匹配），返回 None。
fn classify_operator_phase(
    embedding: &[f32],
    anchors: &[OperatorSemanticAnchor],
    min_similarity: f32,   // 默认 0.3 — 低于此视为无匹配
) -> Option<&'static str> {
    let mut best_op: Option<&str> = None;
    let mut best_sim = min_similarity;

    for anchor in anchors {
        let sim = cosine_similarity(embedding, &anchor.centroid);
        if sim > best_sim {
            best_sim = sim;
            best_op = Some(anchor.operator);
        }
    }

    best_op
}
```

**2.2.3 完整的 per-turn 流程**

```
Turn N (干净上下文，system_prompt = ""):
  ┌─────────────────────────────────────────────────┐
  │ 1. 输入: agent_continue_prompt (结构化引导)      │
  │    system_prompt = ""  ← 关键：移除体系提示词     │
  │                                                 │
  │ 2. LLM 生成                                      │
  │    → result.text (输出文本)                      │
  │    → result.embedding (句子级 embedding)         │
  │                                                 │
  │ 3. EmbeddingObserver.observe(result.embedding)  │
  │    → 映射到 HanziMap 最近汉字                     │
  │    → 更新 semantic_deviation                     │
  │    → 追加到指纹序列                               │
  │                                                 │
  │ 4. 算子语义分类 ← 新增                            │
  │    detected_op = classify_operator_phase(        │
  │        result.embedding, &operator_anchors)      │
  │                                                 │
  │ 5. CangVM 判定 ← 修改                            │
  │    detected_op == expected_op → Pass            │
  │    detected_op != expected_op → Rollback        │
  │    (参第三章：与 YinChecker 的关系)                │
  │                                                 │
  │ 6. Logit Bias 力度调整 ← 修改                     │
  │    real_dev < 0.3: light (off_focus_bias ≈ -0.3)│
  │    real_dev 0.3-0.7: medium (≈ -2.0)           │
  │    real_dev > 0.7: heavy (≈ -4.0)              │
  └─────────────────────────────────────────────────┘
```

**2.2.4 Logit Bias 力度自适应**

当前 bias 力度绑定于 MockEncoder 的固定偏离度，导致始终使用重压制。改为基于真实 semantic_deviation：

```rust
// 当前: off_focus_bias = -lerp(0.3, 4.0, deviation)
//   deviation 恒 ~0.86 → bias 恒 ~-3.5

// 改为:
let real_dev = observer.semantic_deviation();  // 真实值 [0, 1]
let off_focus_bias = -lerp(0.3, 4.0, real_dev);
let divergent_bias = -lerp(0.3, 2.5, real_dev);
// 当模型语义对齐良好时（real_dev < 0.3），bias ≈ 0，几乎不压制
```

**验证指标**：
- 无提示词组 vs 有提示词组：输出质量、轮次完成率、语义偏离度对比
- 分类器准确率：`detected_op == expected_op` 的比率
- Rollback 次数：语义驱动的 Rollback 是否少于正则驱动的 Rollback

#### 第三层：语义词汇 logit bias（可选增强）

**目标**：将 logit bias 从"全局压制"升级为"算子特定推广 + 跨算子压制"。

```rust
struct OperatorLogitBias {
    promote_ids: Vec<u32>,    // 本算子锚定汉字的 token IDs → +bias
    suppress_ids: Vec<u32>,   // 其他算子锚定汉字的 token IDs → -bias
    off_focus_ids: Vec<u32>,  // 全局 off-focus（不变）
    divergent_ids: Vec<u32>,  // 全局 divergent（不变）
}

// 例：当前算子=生
//   promote: 问, 探, 疑, 若, 何 → qwen tokenizer → [64423, 98214, ...]
//   suppress: 深, 聚, 建, 构, ... (长/育的锚定字)
//   off_focus: global (不变)
//   divergent: global (不变)
```

**实现难度**：
- 锚定汉字到 token ID 的映射：直接通过 tokenizer 编码即可（Qwen 中绝大多数汉字是单 token）
- 全词表语义映射：需要读取 `token_embd.weight` 做 152K × 4 余弦计算，可离线预处理

**优先级**：低。第一层和第二层已验证后再考虑。

## 3. 与 YinChecker 的新关系

YinChecker 保留但降级为辅助判定。新的合规判定逻辑变为**双层门控**：

```rust
// Phase 6d+: 双层合规判定
let semantic_match = classify_operator_phase(&embedding, &anchors);
let semantic_ok = semantic_match == Some(expected_operator);
let formal_ok = yin_checker.check(expected_operator, &output_text).is_valid;

// 两层都必须通过
let is_valid = match (semantic_ok, formal_ok) {
    (true, true) => true,           // 语义+形式双重通过
    (true, false) => false,         // 语义对但形式错 → Rollback（形式修正即可）
    (false, true) => false,         // 形式对但语义错 → Rollback（当前假 Pass 的主要来源）
    (false, false) => false,        // 全部错 → Rollback
};
```

这解决了当前最隐蔽的失败模式：**正则碰巧匹配但语义完全错误**（如 Trial 2 输出几何公式但碰巧包含结构化编号，通过育阶段的 YinChecker）。

## 5. 架构抉择

### 5.1 为什么不直接在提示词里缩短/简化体系文本？

缩短提示词可以减轻但无法根除污染。本质问题是 **0.5B 模型的概念容量不足以同时承载"约束框架语义"和"任务语义"**。缩短提示词只是让污染更晚发生，不会阻止模型注意力在两个语义域之间的混淆。

向量汉字映射方案的优势在于：将"约束框架语义"完全移出模型的注意力空间，由外部引擎在 embedding 空间处理。

### 5.2 为什么需要预生成 hanzi_embeddings.bin 而不是实时计算？

- token embedding table（`token_embd.weight`）是模型权重的一部分，已在 VRAM 中。
- 但 llama.cpp FFI 不直接暴露单个 token 的 embedding 向量（`llama_get_embeddings_ith` 需要完整计算图）。
- 从 GGUF 文件离线提取是最高效的方式（`export_hanzi_embeddings.py` 已实现）。

### 5.3 与微调（RouteB）的关系

此方案（向量汉字映射 + 无提示词）与 RouteB 微调是**正交强化**关系：

```
RouteB 微调:  权重层 → 模型自然理解算子语义 → 输出天然对齐
            +
向量汉字映射: 测量层 → 精确感知偏离 → 轻量级纠正
```

当前静默引擎（RouteB + logit bias only）已经验证了"无提示词可行"的假设。本方案将其推广到基座模型。

## 6. 风险矩阵

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| HanziMap 的 300 字不足以精确分类算子语义 | 中 | 语义分类不准 | 先用 Phase 6c 验证偏离度区分力；锚定汉字集可迭代扩展 |
| 0.5B 的 sentence embedding 区分力不足 | 中-高 | 分类器无意义 | 从 trial 数据反向验证：不同任务、不同质量的输出是否有区分力 |
| 移除提示词后模型输出散乱 | 中 | 产出不可用 | 保留 agent_mode 的结构化 continue_prompt（独立于体系提示词） |
| embedding 计算增加延迟 | 低 | 每轮 +~10ms | `ctx_params.embeddings=true` 已启用，无额外转发 |
| 算子锚定汉字选择偏差 | 中 | 分类系统性偏向某个算子 | 从实验数据中提取"模型自然产出中各阶段的高频汉字"校准 |

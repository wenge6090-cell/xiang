# 向量-汉字映射与白箱词表设计

**版本：1.0** | **状态：设计阶段** | **生成日期：2026-05-25**

> 目标：在每个 token 生成步截取 LLM 的输出嵌入，将其映射到有锚定性的汉字，使 LLM 内部的连续向量空间投影到离散符号空间，驱动三易约束引擎实现白箱化约束。
>
> 这是归算子的语义化升级——从 6-bit 汉明距离扩展为"嵌入→汉字→偏离度"的完整语义链路。

---

## 〇、架构定位

### 当前架构（路线A）

```
LLM 输出 → 文本 → 阴仪正则验证 → 偏离度（纯位运算汉明距离）
                              → CangVM 决策
```

偏离度来源：6 位向量的汉明距离。不涉及语义判断。

### 目标架构

```
LLM 输出 → 文本 → 阴仪正则验证
       ↓
   输出嵌入 [2048维]
       ↓
   HanziMap 汉字映射 → ["水","火","金"]
       ↓
   EmbeddingObserver → 语义偏离度 + Gua投影 + 五行偏移
       ↓
   hybrid_deviation(hamming, semantic, alpha) → CangVM 决策
                                              → ShanVM 激活
                                              → ZhouVM 姿态调整
```

偏离度来源：汉明距离（形式） + 汉字语义指纹余弦距离（语义）。这是归算子从"形式观测"到"语义观测"的升级。

### 与六书框架的关系

```
象形字 → 世界实体锚点 → 汉字映射中的"稳定锚"
指事字 → 变化形式化语法 → 八气算子名在字表中的锚定位
会意字 → 复合语义组合 → 卦名关键字的语义载体
假借字 → 语义漂移根源 → 映射偏差的检测信号

归 = 连续向量到离散汉字的翻译器 = 假借的系统性对抗
```

## 一、核心汉字词表设计

### 1.1 设计原则

不穷举。按六书原则精选 300-400 个**有强语义锚定性**的汉字。每个字的字形构造带有"物世界锚点"，使其在嵌入空间中具有稳定可辨识的位置。

### 1.2 三类字表及其作用

**第一类：象形字（~120字）— 实体锚点**

日、月、山、水、火、木、目、耳、口、手、足、心、牛、羊、马、鸟、鱼、虫、门、户、车、舟、网、弓、矢、刀、衣、皿、鼎、豆、戈……

每个字锚定一种世界实体。在嵌入空间中形成最稳定的聚类——因为无论上下文如何，"日"总指向太阳。

**第二类：指事字（~120字）— 变化语法**

- 数字系列：一至十、百、千、万
- 方位系列：上、下、左、右、前、后、中、内、外
- 对比系列：大、小、多、少、长、短、高、低
- 时间系列：古、今、先、后、初、终、旦、夕
- 动作指示：入、出、分、合、交、反、正、曲、直
- **八气算子名**（必须包含）：生、动、长、育、杀、止、归、藏
- **八卦名**（必须包含）：乾、兑、离、震、巽、坎、艮、坤

这些字编码抽象关系和变化过程。八气算子名在字表中的位置就是八种核心操作的语义锚点。

**第三类：会意字（~120字）— 复合概念**

明（日月）、休（人倚木）、信（人言）、武（止戈）、森（三木）、众（三人）、晶（三日）、安（女在宀下）、家（宀中有豕）、化、变、通、达、成、败、得、失、安、危……

卦名中的关键字也在此列。复合字携带"关系语义"，帮助判断偏离是否属于"概念漂移"（如从"家"滑向"休"→ 偏离度低，从"家"滑向"危"→ 偏离度高）。

### 1.3 数据结构

`crates/xiang-core/src/hanzi_table.rs`：

```rust
pub enum HanziCategory {
    Pictogram,         // 象形 — 实体锚点
    Ideogram,          // 指事 — 变化语法
    CompoundIdeogram,  // 会意 — 复合概念
}

pub struct HanziEntry {
    pub ch: char,
    pub category: HanziCategory,
    pub tag: &'static str,      // 语义标签
    pub wuxing: Option<WuXing>,  // 五行归属（如适用）
}

pub const HANZI_TABLE: [HanziEntry; N] = [...];
```

## 二、模型嵌入表提取方案

### 2.1 原理

利用 Qwen3.5-4B 自身的 token embedding 矩阵（`token_embd.weight`，shape `[vocab_size, n_embd]`）。将字表中每个汉字的 token embedding 提取出来，作为"锚点嵌入"。

**为什么用模型自身 embedding 表：** 模型自身 embedding 空间和输出嵌入在同一个几何空间中。LLM 的输出嵌入直接与字表嵌入做余弦相似度，不存在分布漂移。如果用外部 encoder（如 BGE），两个嵌入空间可能不重合。

### 2.2 离线导出流程

```
1. 加载 Qwen3.5-4B GGUF 文件
2. 读取 tensor "token_embd.weight" → shape [152064, 2048]
3. 对字表中每个汉字:
   a. tokenize(字符) → token_id
   b. token_embd[token_id] → 2048 维向量
   c. L2 归一化
4. 写入 hanzi_embeddings.bin
```

格式：`[u32 n_chars] [u32 n_embd] [(u32 char_utf32, u32 token_id, f32×n_embd) × n_chars]`

输出大小：400 字 × 2048 × 4 bytes ≈ 3.3 MB。

### 2.3 运行时加载

```rust
// crates/xiang-core/src/hanzi_map.rs
const EMBEDDINGS_BIN: &[u8] = include_bytes!(concat!(env!("OUT_DIR"), "/hanzi_embeddings.bin"));

pub struct HanziMap {
    chars: Vec<char>,
    embeddings: Vec<Vec<f32>>,  // 已 L2 归一化
    entries: Vec<HanziEntry>,
}
```

编译时嵌入，零文件路径依赖。

## 三、llama.cpp 嵌入拦截实现

### 3.1 当前状态

- `llama_get_embeddings_ith(ctx, i)` FFI 函数可用，返回 `[n_embd]` 维度的浮点数组
- `llama_n_embd(model)` 可用于获取嵌入维度
- Rust FFI 绑定了 `ctx_params` 结构体（含 `embeddings` 字段），但当前未设置为 `true`
- 当前代码已设置 `batch.logits[last] = true`，这同时启用 logits 和 embeddings

### 3.2 修改点

**文件：`crates/xiang-llm/src/llama_backend.rs`**

1. 在 `LlamaCppBackend::new()` 中设置 `ctx_params.embeddings = true`
2. 添加 `llama_n_embd` FFI 声明并存储到 `self.n_embd: usize`
3. 添加 `llama_get_embeddings_ith` FFI 声明
4. 在 `generate_with_logit_bias` 的每步解码后提取嵌入：

```rust
let emb_ptr = llama_get_embeddings_ith(self.ctx, batch.n_tokens as i32 - 1);
let embedding: Vec<f32> = std::slice::from_raw_parts(emb_ptr, self.n_embd).to_vec();
```

**文件：`crates/xiang-llm/src/lib.rs`**

5. `GenerateResult` 新增字段 `pub embedding: Option<Vec<f32>>`

### 3.3 性能影响

- 嵌入提取是纯内存拷贝（`2048 × 4 bytes = 8 KB`），耗时远小于 1μs
- 不影响推理速度（2.3 tok/s，每 token 间隔 ~435ms）
- Vulkan 后端兼容性：需实测确认。如不支持，备选方案为 CPU-only 模式做 embeddings 提取

## 四、向量-汉字映射算法

### 4.1 核心算法

```
输入: output_embedding: &[f32]  (n_embd 维)
      字表嵌入: hanzi_embeddings  (N 个，已 L2 归一化)
输出: Vec<(char, f32)>  (汉字 + 余弦相似度, top-K)

1. L2 归一化 output_embedding
2. 对 i = 0..N:
     sim[i] = dot(output_embedding, hanzi_embeddings[i])
3. 选 top-K 最大 sim 值 → 返回字符 + 相似度
```

### 4.2 性能分析

- N ≈ 400 字，n_embd ≈ 2048
- 每次检索：400 × 2048 ≈ 819K f32 乘加 ≈ 0.82 MFLOPS
- CPU 执行时间：< 0.1ms（现代 CPU 单核 ~50 GFLOPS）
- 与推理速度（435ms/token）相比：延迟影响 < 0.02%
- **不需要近似索引，暴力遍历已足够**

### 4.3 `HanziMap` API

`crates/xiang-core/src/hanzi_map.rs`：

```rust
impl HanziMap {
    /// 从 include_bytes! 嵌入数据构建
    pub fn from_embedded_bytes() -> Self;

    /// K=1 映射
    pub fn map_single(&self, emb: &[f32]) -> (char, f32, &HanziEntry);

    /// K=3 映射（用于多字组合语义）
    pub fn map_top_k(&self, emb: &[f32], k: usize) -> Vec<(char, f32, &HanziEntry)>;

    /// 相似度 ≥ threshold 的所有汉字
    pub fn map_with_threshold(&self, emb: &[f32], t: f32) -> Vec<(char, f32, &HanziEntry)>;
}
```

## 五、EmbeddingObserver：映射结果驱动约束

### 5.1 新组件设计

`crates/xiang-core/src/embedding_observer.rs`：

```rust
pub struct EmbeddingObserver {
    hanzi_map: HanziMap,
    history: VecDeque<Observation>,     // 最近 N 步观测
    focus_anchors: Vec<(char, f32)>,    // 问题焦点的汉字锚
}
```

每步方法：

```rust
pub fn observe(&mut self, embedding: &[f32]) -> Observation;
```

### 5.2 Observation 输出

```rust
pub struct Observation {
    pub top_char: char,              // K=1
    pub top_3_chars: [char; 3],      // K=3
    pub top_3_sims: [f32; 3],        // 对应相似度
    pub gua_projection: Gua,         // 嵌入投影到 6-bit Gua
    pub semantic_deviation: f32,     // 与焦点锚点的语义偏离度
    pub element_shift: [f32; 5],     // 五行分布变化 (金木水火土)
}
```

### 5.3 语义偏离度计算

**核心创新：汉字基投影。**

不用双 LLM（路线C）做语义判断。用同样的 HanziMap 建立"语义指纹"：

```
1. 对用户输入做嵌入提取 → 汉字映射 → top-10 相似度向量 V_Q
2. 对每步输出做嵌入提取 → 汉字映射 → top-10 相似度向量 V_A
3. semantic_deviation = 1.0 - cosine_similarity(V_Q, V_A)
```

如果 LLM 的思考方向（从输出嵌入看）与用户问题焦点（从输入嵌入看）在同一个汉字语义域中，则偏离度低。偏离到不同域则偏离度高。

### 5.4 Gua 投影

利用已有的 `project_embedding_to_bits()`（`cang_sea.rs`），将输出嵌入投影为 6-bit Gua：

```
embedding[0..6] → 每维正负 → 对应 bit 是否置位
```

这保持了与现有 CangVM 的兼容性。

### 5.5 五行元素偏移

从汉字映射结果中提取五行标签，累计近 N 步的元素分布变化：

```
金（兑/乾） 木（震/巽） 水（坎） 火（离） 土（坤/艮）

如果 LLM 输出持续偏向"火"域字符 → ZhouVM 调节温度倾向 离卦（明照）
如果分布突然跳跃 → 可能发生了概念漂移
```

## 六、与三易引擎的完整接线

### 6.1 CangVM 修改

`crates/xiang-cangvm/src/vm.rs`：

- 新增字段 `embedding_observer: Option<EmbeddingObserver>`
- `set_semantic_origin(text)` 升级：对 origin text 做 embedding → 存储焦点锚
- `current_deviation()` 升级：返回 `hybrid_deviation(hamming, semantic, alpha)`
  - alpha 可配，默认 0.3（70% 汉明权重 + 30% 语义权重）保守起步

### 6.2 ZhouTian 每步循环增强

每 token 步后（在 `generate_with_logit_bias` 之后）：

1. 从 `GenerateResult.embedding` 提取输出嵌入
2. `observer.observe(emb)` → Observation
3. `Observation.semantic_deviation` → 喂入 `hybrid_deviation()`
4. `Observation.element_shift` → ZhouVM 姿态调节
5. `Observation.gua_projection` → 与 CangVM 的 Gua 状态比对（验证一致性）

### 6.3 连山激活增强

```
当前：deviation > 0.5 → 激活 ShanVM
升级：semantic_deviation 单独或混合触发
  - semantic_dev > 0.7 → 强制激活（即使 hamming_dev 低）
  - semantic_dev 持续上升 > 3 步 → 预警性激活
```

### 6.4 藏海写入

已有 `SemanticStore.store_semantic()` 接口（`cang_sea.rs`）。写入内容升级：

```
SemanticEntry {
    v_semantic: embedding,        // 输出嵌入
    v_think: observation.top_3_chars, // 离散汉字序列
    reward: 1.0 - semantic_deviation,
}
```

### 6.5 接线总表

| 组件 | 当前状态 | 升级后 |
|:---|:---|:---|
| CangVM::deviation | 纯汉明 | `hybrid_deviation(hamming, semantic, 0.7)` |
| CangVM::judge | 汉明阈值 | 汉明 + 语义复合阈值 |
| ZhouVM 温度 | 汉明混合 | 汉明 + 五行元素偏移混合 |
| ShanVM 激活 | dev > 0.5 | dev > 0.5 或 semantic_dev_rising |
| 藏海存储 | 仅离散状态 | 离散状态 + 嵌入向量 + 汉字序列 |
| 上下文代谢 | 无切入 | 汉字序列驱动截断判断 |

## 八、风险与缓解

| 风险 | 缓解 |
|:---|:---|
| Vulkan 后端不支持 embeddings 提取 | 备选：CPU-only llama.cpp 做 embeddings 提取；或用独立 GGML 上下文 |
| 400 字表覆盖不足，高频字缺失 | 字表以六书为纲，有锚字优先；后续可扩展至 ~800 字 |
| 语义偏离度与汉明偏离度冲突 | alpha 保守起步 0.3；可动态调节 |
| Qwen3.5 embedding 维度未知 | 运行时 `llama_n_embd()` 动态获取 |

## 九、数据流全图

```
用户输入 "如何设计数据库？"
  │
  ├──→ tokenizer → token embedding → HanziMap → 焦点锚: {设,计,数,据,库}
  │                                                      ↓
  │                                            EmbeddingObserver.focus_anchors
  ▼
ZhouTian 循环
  │
  ├── CangVM 算子: 生 → 动 → 长 → 育
  │
  ├── llama_decode() → 文本（阳）
  │       │
  │       └──→ llama_get_embeddings_ith() → [2048维] 输出嵌入
  │                    │
  │                    ├──→ logits → bias → sample → 文本生成
  │                    │
  │                    └──→ HanziMap.map_top_k(emb, 3)
  │                              │
  │                         ["探", "索", "问"]  (离散汉字)
  │                              │
  │                    EmbeddingObserver.observe()
  │                              │
  │              ┌───────────────┼───────────────┐
  │              ▼               ▼               ▼
  │       semantic_dev    gua_projection    element_shift
  │              │               │               │
  │              ▼               ▼               ▼
  │       hybrid_dev()      CangVM judge    ZhouVM 姿态
  │       hamming 0.3      ShanVM 激活     温度调节
  │       + semantic 0.7
  │              │
  │              ▼
  │       归算子 → 真正的语义偏离判断
  │       不再是位运算，而是"水火金"vs"设计数库"的距离
```

# 硬件适配与异构部署方案

**版本：1.0** | **状态：设计完成**

> 本文档汇总在有限硬件条件下（8GB 显存 GPU + 48GB 内存 CPU）运行三易系统的工程方案。  
> 涵盖量化策略、MoE 专家设计、异构架构、LoRA 训练可行性、上下文管理。

---

## 〇、硬件约束

| 组件 | 容量 | 角色 |
|------|:---:|------|
| GPU 显存 | 8GB | LLM 推理（阳仪生成） |
| CPU 内存 | 48GB | 阴仪编码、藏海向量库、三易控制平面、专家模型库 |

---

## 一、量化策略

8GB 显存无法运行 FP16 的 4B 模型并同时加载 LoRA 和 KV Cache。

| 方案 | 底座模型显存 | LoRA 专家 | 剩余 | 可行性 |
|------|:---:|:---:|:---:|:---:|
| FP16 底座 | ~8GB | 无法加载 | 0GB | ❌ |
| 8-bit 量化 | ~4-5GB | +160MB | ~3GB | ⚠️ 紧 |
| 4-bit 量化 (Q4_K_M) | ~2.5-3GB | +160MB/个 | ~4-5GB | ✅ |

**推荐**：GGUF Q4_K_M 量化格式，4B 模型约 2.5GB，足够与系统上下文、KV Cache 共存。

## 二、异构架构：GPU + CPU 双引擎

```
┌───────────────── GPU (8GB) ─────────────────┐
│                                              │
│  当前活跃4bit量化4B专家 (2.5GB)              │
│  · 快速生成 (10-30 tokens/s)                │
│  · 当前是"创造专家"还是"审慎专家"，          │
│    取决于三易系统刚刚从CPU调入的模型权重。    │
│                                              │
└──────────────────────────────────────────────┘
                        ▲
                        │ PCIe 切换 (2-3秒)
                        ▼
┌───────────────── CPU (48GB) ────────────────┐
│                                              │
│  专家模型库 (量化，约10GB)                    │
│  · 创造生成者 · 审慎执行者 · 反思诊断者 · 编码者   │
│                                              │
│  阴仪编码模型 (约0.5GB)                      │
│  · 计算语义偏离度                            │
│                                              │
│  藏海v2 向量库 (可扩展至数GB)                 │
│  · 经验检索 · 免疫记忆 · 策略向量             │
│                                              │
│  三易控制平面 (纯CPU)                        │
│  · 归藏 · 连山 · 周易 · 主循环              │
│                                              │
└──────────────────────────────────────────────┘
```

**核心分工**：
- GPU：只跑阳仪（生成），始终只有一个活跃模型
- CPU：阴仪编码、藏海检索、三易控制平面、多专家待命

## 三、MoE：4B 模型的专家拆分

### 设计思路

不是横向扩展参数（8×7B），而是纵向拆分能力：共享躯干，拆分大脑皮层。

保留约 2B 参数的共享底座（处理基础语法和常识），插入多个约 0.3-0.5B 参数的轻量 LoRA 专家模块。推理时底座始终在显存中，只动态加载当前需要的 1-2 个专家。

### 四专家设计

| 专家 | 周易姿态 | 连山策略 | 训练数据特征 |
|------|---------|---------|------------|
| 创造生成者 | 乾(温度1.2) | 强力突破 | 发散性强、偏离度0.3-0.6的样本 |
| 审慎执行者 | 坤(温度0.6) | 继续 | 严格遵守原语、偏离度<0.2的样本 |
| 反思诊断者 | 离(温度0.5) | 拆解分解 | 自我纠偏、迂回绕行成功的样本 |
| 语义编码者 | 艮(温度0.3) | 等待收集 | 总结、提取、晶体化的样本 |

### 三阶段演进

**第一阶段：生成专家种子，数据自动分流**
让 4B 模型跑各种任务，三易系统自动将输出打上标签，按标签自动分箱。

**第二阶段：拆分专家模块，单卡动态路由**
为底座模型分别训练 4 套 LoRA 权重（每套约 0.3-0.5B 参数）。三易系统在每一步算子执行前发出路由指令，加载对应的 LoRA 专家（卸载/加载约 100ms）。

**第三阶段：经验回流与自我蒸馏**
专家产出的高质量结果成为彼此的"教材"。路由信号本身就是指令，构建纠正数据集进行自我蒸馏。

### LoRA 专家参数

- 全量 4B 模型：约 40 亿参数
- 一个 LoRA 专家（rank=16）：约 2000-4000 万参数（0.5%-1%）
- 一个 LoRA 权重文件：约 80-160MB（FP16）
- 推理时 LoRA 权重直接合并进底座模型，计算量几乎不增加

## 四、训练可行性

### 本地训练

| 模式 | 8GB 显存 | 16GB 显存 |
|------|:---:|:---:|
| 推理 4B 模型（FP16） | ⚠️ 勉强 | ✅ 宽裕 |
| 推理 4B 模型（4-bit） | ✅ 宽裕 | ✅ 极宽裕 |
| 训练 LoRA 4B 模型（FP16） | ❌ 需~14-16GB | ✅ 刚好 |
| 训练全量 4B 模型 | ❌ 需~32-48GB | ❌ 仍需更多 |

**8GB 本地训练不可行**。推荐云端训练 + 本地推理：
1. 用 llama.cpp 的 quantize 将 4B 模型量化为 Q4_K_M
2. 本地推理（~2.5GB 显存）
3. LoRA 训练放在云端（Google Colab / AutoDL），训完下载 80-160MB 的权重文件

### 训练耗时估算

| 阶段 | 操作 | 耗时（4B，单张 24G 显卡） |
|------|------|:---:|
| 1. 跑数据 | 日常使用，三易自动打标签 | 约 1-2 周，积累 5000+ 条 |
| 2. 训 LoRA 专家 | 每个专家微调 | 约 3-6 小时/个 |
| 3. 自我蒸馏 | 用专家产出纠正底座 | 约 1-3 小时 |

冷启动到第一个专家上线：约 3-6 小时。四个专家全上线：约 15-24 小时。持续进化：每积累 1000 条新高质数据，追加微调约 1 小时。

## 五、偏离检测的 CPU 侧性能

所有偏离检测器在 CPU 上运行，流程：

| 检测器 | 技术 | 耗时 |
|--------|------|:---:|
| n-gram 重复率 | 纯统计 O(n) | < 1ms |
| 长度异常 | O(1) | < 0.1ms |
| 结构合规 | 规则+模板匹配 | < 1ms |
| 语义漂移 | 轻量嵌入模型（MiniLM）+ 余弦距离 | 5-10ms |
| 幻觉特征 | 规则库扫描 | 1-3ms |
| 汇总判断 + 连山决策 | 纯条件分支 | < 0.1ms |

**检测总耗时 < 20ms**。对比 4B 模型单轮生成延迟（500ms-2000ms），检测开销占比 < 2%，用户无感知延迟。

## 六、token 级 vs 轮级干预

### token 级实时干预不可行

三个硬约束：
1. **无可靠的瞬时偏离信号**：偏离是序列级属性，不能从中间截断判定
2. **思维链连续性不可破坏**：强制截断或重定向 logits 会打断注意力流
3. **工程复杂度与收益不匹配**：每 token 干预拖慢生成速度 2-5 倍

### 轮级后处理（当前架构最优）

流程：
1. LLM 生成完整响应（GPU）
2. CPU 并行计算多维偏离向量（< 20ms）
3. 偏离度超标 → 本轮输出不追加到历史 → 调整姿态/策略 → GPU 重新生成
4. 不超标 → 追加到历史，继续下一轮

**优势**：不破坏思维链、不拖慢生成、不影响 GPU 吞吐。

## 七、上下文噪点管理

8GB 显存的 4B 模型有效上下文窗口短（4k-8k），需要 CPU 端三层治理：

**第一层：门槛拦截（本轮丢弃）**
偏离度超标 → 本轮输出不追加到历史。不进入上下文的数据不产生污染。

**第二层：滑动窗口裁剪**
上下文长度超过模型有效窗口时，按轮次边界截断最早内容，确保保留完整的三元组结构。

**第三层：语义压缩替代原始文本**
超出窗口的旧轮次不直接保留原始输出。用 CPU 上的阴仪模型压缩为状态摘要向量 + 关键决策记录：
```
[历史摘要：上轮偏离度0.2，策略绕行成功，结果达标]
```
这比原始文本节省 90%+ 的 token 空间，且消除旧文本中的风格污染。

### 为什么不改模型注意力层

- 稀疏注意力需改动模型结构，与"4B 模型不动核心架构"的约束冲突
- 对小模型（4B），稀疏注意力的计算节省有限，实现复杂度显著增加
- 语义级噪点无法在注意力层识别——是语义问题，不是 token 位置问题

**结论**：保持模型内部全注意力/GQA 不变，在 CPU 端做上下文管理和噪点治理。

---

## 八、与更强模型（DeepSeek V3 等）的关系

DeepSeek V3 等强模型的混合注意力（CSA/HCA/SWA）是模型内部机制的创新，解决的是 1M token 上下文中的信噪比问题。三易系统是模型外部的控制层创新，解决的是认知过程的结构化引导问题。

两者不是竞争关系，是互补层：
- 强模型是更强的"发动机"
- 三易是模型无关的"整车控制系统"
- 更强模型反而更需要精确的外部控制系统来驾驭

三易系统的偏离检测、策略导航、姿态调节、经验积累对任何模型（包括 V4）都有效。

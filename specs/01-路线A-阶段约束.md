# 路线A：阶段约束 — 归藏引擎实现方案

**版本：4.0** | **难度：⭐** | **状态：✅ 观测层+干预层+管理层分阶实现中**

> 在现有 LLM 之上叠加硬约束思考控制系统。不改变模型权重，通过常规验证、算子协议、CangVM 状态机，确保思考有纪律、跑偏可纠正。
>
> **核心设计原则**：所有约束是程序化的（Logit-Bias / 正则 / 状态机），不是自然语言的。程序化约束由引擎层静默执行，不暴露给 LLM。
>
> **实验提示词策略（v3.1 新增）**：由于路线A 未对模型进行微调，模型缺乏对三易约束体系的先验知识。为模拟微调后的认知能力，实验组和对照组均在系统提示词中注入三易约束体系全文，工程态信息（算子/姿态/偏离度/连山决策）仅注入实验组。详见 §八。
>
> **与三易统一的关系**：路线A 对应**归藏（GuiZang）**引擎——三易之一，负责"心之律"（意识循环）。连山（策略导航）和周易（认知姿态）的代码已就绪，在路线B启动后接入流水线。

## 二、核心组件

### 2.1 八气算子协议

| 算子 | 类型 | 协议要求 | 实现位置 |
|:---|:---|:---|:---|
| **生** | 干预 | Logit-Bias 鼓励探索 token 池 | xiang-llm (XiangLogitBias) |
| **动** | 干预 | Logit-Bias 鼓励发散 token 池 | xiang-llm (XiangLogitBias) |
| **长** | 干预 | Logit-Bias 鼓励收敛 token 池 | xiang-llm (XiangLogitBias) |
| **育** | 干预 | Logit-Bias 鼓励结构 token 池 | xiang-llm (XiangLogitBias) |
| **归** | 观测 | 偏离度 = hybrid(hamming, semantic, alpha) + HanziMap 汉字投影 | xiang-core (deviation.rs + embedding_observer.rs) |
| **杀** | 管理 | 上下文裁剪：偏离 > 0.7 时删除最近 N 轮对话历史 | xiang-cangvm (信号) → xiang-chat (执行) |
| **止** | 管理 | 上下文冻结：偏离 > 0.5 时停止追加新信息 | xiang-cangvm (信号) → xiang-chat (执行) |
| **藏** | 管理 | 上下文清空：周天完成时保留摘要，重置对话上下文 | xiang-cangvm (信号) → xiang-chat (执行) |

### 2.2 阴仪：阶段协议验证器

阴仪**不是**语义理解器，而是**正则规则匹配器**。只检查形式是否符合算子阶段规范。

| 算子 | 必须包含 | 禁止出现 | 结构 |
|------|---------|---------|------|
| **生** | 试探词(也许/可能/?) + 开放词(如何/是否) | 结构词(第一步/因此) | 自由 |
| **动** | 发散词(此外/另一方面/还可以) | 结论词(最终/应该) | 段落式 |
| **长** | 聚焦词(重点/沿着/深入) | 发散词(也许/另一个思路) | 单一路径 |
| **育** | 编号结构(第一步/1.) | 模糊词(也许/可能) | 编号列表 |

> **已实现**: `crates/xiang-core/src/yin_checker.rs` — 15 个单元测试覆盖。

### 2.3 CangVM：硬逻辑状态机

```
      [生]───(通过)→[动]───(通过)→[长]───(通过)→[育]──(通过)→[藏]
        │              │              │              │
        │(失败)        │(失败)        │(失败)        │(失败)
        ▼              ▼              ▼              ▼
      [归]          [归]          [归]          [归]
        │              │              │              │
        ├─重试<MAX──→[生]         ...             ...
        │
        └─重试≥MAX──→[杀]──→[下一算子] 或 [止]──→[藏]

周期内累计杀次数≥MAX_KILLS → [止] → [藏]
```

**决策参数**：单算子最大重试 2 次 | 周期最大杀 3 次 | 全局最大重试 5 次

**决策指令**：
- `PASS` — 通过，进入下一算子
- `ROLLBACK` — 回滚，重试同一算子
- `SKIP` — 跳过，强制进入下一算子
- `STOP` — 终止，进入藏
- `FINISH_CYCLE` — 完成，进入藏

> **已实现**: `crates/xiang-cangvm/src/vm.rs` — `CangVMDecision` 枚举 + `judge()` 方法 + `ZhouTianRunner::run_phase_cycle()`，16 个单元测试覆盖。

### 2.4 三层认知约束（v4.0 重新划分）

v4.0 根据第一性原理对三层进行了重新定位——从"技术实现"角度切换到"认知过程"角度：

| 层 | 定位 | 工具 | 状态 |
|:---|:-----|:----|:----:|
| Layer 1：观测层 | 归 + HanziMap —— 只观测，不干预 | EmbeddingObserver → 汉字投影轨迹 → 语义偏离度 | 🔧 P0 接线中 |
| Layer 2：干预层 | 生→动→长→育 —— 生成时 token 级方向引导 | 算子差异化 Logit-Bias（四组专属 token 池，±1.0上限） | 📋 P1 待做 |
| Layer 3：管理层 | 杀→止→藏 —— 生成后上下文管理 | 对话历史裁剪 + 上下文冻结 + 清空重置 | 📋 P1 待做 |

**设计原则**：
- 观测优先：任何时候都接上。即使 HanziMap 不可用（降级为纯 Hamming）。
- 引导其次：只做方向引导，不做内容压制。强度上限 ±1.0。
- 清理最后：只处理已发生的偏离，不预防未发生的内容。

**与 v3.x 的差异**：
- v3.x 将 Layer 2 设计为"硬偏置（-8.0 强压制）"，v4.0 下调为"方向引导（±1.0）"
- v3.x 的"上下文代谢"仅用于文本摘要，v4.0 升级为"杀/止/藏驱动的真实上下文操作"
- v3.x 没有独立的观测层，v4.0 将归+HanziMap 提升为独立 Layer 1

## 四、与三易统一的关系

### 4.1 路线A = 归藏引擎

```
路线A（外挂约束）   ←→   归藏引擎    ←→  三易之一（心之律）
```

路线A 实现了三易中的**归藏**层。连山和周易的 Rust 代码已就绪但尚未接入流水线——这是路线B 的核心任务。

### 4.2 藏海数据飞轮

路线A 不仅是一个约束系统——它还是一个**数据生产流水线**。每次周天循环产生：
- 问题文本 + 模型输出
- 偏离度（hamming distance）
- 卦象状态转移
- Judge() 决策（PASS/ROLLBACK/SKIP/STOP）

这些数据经质量筛选后存入藏海，成为路线B 微调数据的核心来源。这是"自举进化"飞轮的基础：

```
路线A 约束引擎 → 生产质量过滤数据 → 存入藏海
                                      ↓
                          路线B LoRA 微调 ← 读取藏海经验数据
                                      ↓
                           模型内化算子 → 更准确的约束
                                      ↓
                           路线A 获得更好基础 → 更高质量数据...
```

## 八、实验提示词策略（v3.1）

### 8.1 问题背景

路线A 的设计假设是"所有约束程序化，引擎状态不注入提示词"。但该设计隐含了一个前提：**模型已经微调，具备对三易约束体系的先验知识**。

当前系统尚未对模型进行 LoRA 微调（路线B 未启动），模型完全不知道三易约束体系的含义。如果不在提示词中告知约束体系，约束实验组和裸奔对照组的 LLM 将是在同一个"黑箱"上运行，实验无法隔离**约束体系知识的存在与否**这一核心变量。

### 8.2 实验设计

| 组别 | 系统提示词构成 |
|------|---------------|
| **约束实验组 LLM** | 三易动态提示词 + 模型参数 + **三易约束体系全文** |
| **对照组裸奔 LLM** | **只有三易约束体系全文** |

**三易约束体系全文**：以 [05-三易算法内核.md](./05-三易算法内核.md) 为蓝本的精简全文，包含：
- 三易三层职责（归藏/连山/周易）
- 八气算子协议（生/动/长/育/杀/止/归/藏）
- 八卦认知姿态体系
- 偏离度方法论
- 阴仪正则验证规则
- 连山六步决策链

**三易动态提示词**（仅注入实验组）：引擎运行时状态编译为自然语言，包含：
- **归藏**：当前算子 → 阶段提示（起念探索/发散联想/收敛聚焦/方案分解），偏离度 → 偏离描述（低/中/高）
- **周易**：当前姿态 → 姿态描述（创造/表达/明照/启动/渗透/破局/止定/承载），温度值
- **连山**：偏离度 > 0.5 时触发 → 障碍导航段落（受阻次数/决策方向）

### 8.3 实验等价性分析

```
约束实验组提示词 = 三易约束体系全文 + 三易动态提示词 + 模型参数
对照组裸奔提示词 = 三易约束体系全文

实验变量 = (三易约束体系全文 + 三易动态提示词 + 模型参数) - (三易约束体系全文)
         = 三易动态提示词 + 模型参数
```

两边都拥有三易约束体系全文 → 模拟了微调后的"知识注入"，两组模型都知道约束体系的存在和规则。
三易约束体系全文在两组中"相互抵消" → 它不是实验变量。
**真正的实验变量**：三引擎运行时状态（算子/姿态/偏离度/温度/连山决策）是否注入提示词。

### 8.4 预期效果

1. **信息量压力**：三易约束体系全文占比很大，对小模型的多轮思维链构成更大压力，更能暴露约束系统的真实作用
2. **思维链分化**：实验组每次收到不同的动态提示词（2048 种之一），对照组每次收到相同的静态体系全文，多轮对话中思维链将产生可测量差异
3. **等价微调模拟**：两组都注入约束体系全文，等效于模型都经过了"知识微调"，使实验条件逼近路线B 的微调后场景

### 8.5 对比原有设计的差异

| 维度 | v3.0 原设计 | v3.1 新设计 |
|------|:----------:|:----------:|
| 实验组 system_prompt | ProjectContext 关键决策（极简） | 三易动态提示词 + 三易约束体系全文 + ProjectContext |
| 对照组 system_prompt | 空（无任何约束信息） | 三易约束体系全文 |
| 实验变量 | 约束引擎 on/off | 引擎运行时状态注入 on/off |
| 模型先验知识 | 依赖（实际缺失） | 通过文本注入等价获得 |
| 小模型压力 | 低（极简提示词） | 高（体系全文信息量大） |

> **关键洞察**：v3.0 的"零提示词注入"相当于要求模型在不知道什么是三易的情况下遵守三易约束——这是不合理的。v3.1 通过双方都注入体系全文来消除这一不公平前提，让实验变量回归到它本来的位置：**三引擎的运行时引导是否有效**。

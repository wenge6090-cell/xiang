# 路线B：控制原语微调 — 行为内化方案

**版本：2.1** | **难度：⭐⭐** | **状态：设计完成，当前硬件阻塞（可选方案）**

> 将八气算子从"外部约束协议"内化为模型的行为本能。通过**词表扩展 + 控制原语嵌入 + LoRA 微调**，降低 LLM 对约束体系的对抗性。
>
> **在推理链中的位置（见 [10-第一性原理审视.md](./10-第一性原理审视.md) §6.3）**：LoRA 微调实现的是**行为内化**（模型更听话），不是**认知内化**（模型内部状态变得可观测）。三易引擎承担认知判断，LLM 只需在认知框架内"好好说话"。路线B 的价值在于降低外部约束的对抗成本，不是让黑箱变白箱。
>
> **在三易统一中的位置**：路线B 是归藏引擎的优化步骤——将外挂约束转化为模型原生行为响应。连山和周易的流水线接线已解耦为独立任务，不阻塞路线B 执行。
>
> **数据来源革命**：路线A 的 CangSea 已在 4B 模型上积累质量过滤数据。路线B 的数据源从"纯教师模型蒸馏"升级为**"藏海沉淀 + 教师蒸馏"双通道**——这是自举进化飞轮的第一圈。

**前置依赖**：✅ 路线A 已完整实现（归藏引擎 + HttpBackend + 词表基础设施）

## 二、数据飞轮：藏海驱动微调

### 2.1 双通道数据源

路线B 的训练数据来自两个源头：

**通道1：藏海沉淀数据（核心差异化）**
```
路线A 运行时积累 → 每周天产生一条藏海条目
                  → 每条含：问题、输出、偏离度、卦象、judge 决策
                  → 质量过滤：偏离度 < 0.3 + judge == PASS 的数据为高质量
                  → 自动标注：每条数据的算子边界 + 八气标签
                  → 无需人工标注
```
- 数据量：每 1000 轮对话产生 ~800 条高质量标注数据
- 优势：**与当前模型行为分布一致**，不存在教师-学生分布偏移
- 瓶颈：冷启动时数据不足（需 ≥500 条高质量数据启动微调）

**通道2：教师模型蒸馏（冷启动辅助）**
```
大模型（Qwen2.5-72B / GPT-4）生成带控制原语的推理数据
                  → 覆盖藏海冷启动期的数据缺口
                  → 多领域覆盖：编程、数学、法律、医疗、创意写作
```
- 数据量：5000-10000 条（合成）
- 优势：快速启动，领域覆盖广
- 劣势：教师-学生分布可能不匹配

### 2.2 冷启动 → 自举闭环

```
Phase 1: 冷启动
  教师模型生成 ~10K 条合成数据 → 首次 LoRA 微调
  → 模型获得基础的控制原语理解能力

Phase 2: 半自举
  路线A 约束引擎以微调后模型运行 → 藏海积累质量过滤数据
  → 每积累 500 条高质量数据 → 增量 LoRA 微调
  → 模型能力提升 → 藏海数据质量提升

Phase 3: 自举
  藏海数据量 > 教师合成数据量 → 微调数据以藏海为主
  → 教师模型退出
  → 完全自给自足的数据飞轮
```

### 2.3 数据格式

```
训练样本格式（通道1：藏海 → 自动标注）：
<U+E000>针对问题：{用户问题}，请起念探索。<U+E001>
<阳仪生成的生算子内容>
<U+E002>针对以上方向，请发散联想。<U+E003>
<阳仪生成的动算子内容>
<U+E004>请从发散中收敛一条明确路径。<U+E005>
<阳仪生成的长算子内容>
<U+E006>请将所选路径分解为具体步骤。<U+E007>
<阳仪生成的育算子内容>
```

## 三、控制原语定义

### 3.1 算子控制原语（14 个）

使用 Unicode 私有区字符，保证不与任何自然语言 token 冲突。

```
生成算子启动/结束:
  生_start: U+E000    生_end: U+E001
  动_start: U+E002    动_end: U+E003
  长_start: U+E004    长_end: U+E005
  育_start: U+E006    育_end: U+E007

控制算子 (CangVM 内部使用，不要求阳仪生成):
  归: U+E010    杀: U+E011    止: U+E012    藏: U+E013
```

### 3.2 控制原语的嵌入向量初始化

不随机初始化，而是用**base model 的 transformer 编码器**对每个算子的中文语义描述进行编码，得到语义向量。

```
算子语义描述（用于生成初始嵌入）:
  生: "起念探索，萌发初步思路，提出开放性问题或假设。"
  动: "发散联想，多角度扩展，列举相关维度和可能性。"
  长: "收敛聚焦，明确选择一条分析路径。"
  育: "方案分解，结构化列出具体步骤或子任务，确定性描述。"
  归: "偏离检测，校验当前输出是否符合算子规范。"
  杀: "截断回滚，丢弃违规输出，恢复至安全状态。"
  止: "周期终止，提前结束当前周天。"
  藏: "经验沉淀，将思考过程存入记忆库。"
```

**初始化步骤**：
1. 添加新 token 到 tokenizer
2. 扩展词表嵌入矩阵（`model.resize_token_embeddings`）
3. 用 base model 的 transformer 编码语义描述文本
4. 取最后一层 hidden states 的均值作为对应 token 的嵌入向量
5. 直接写入 embed_layer.weight

## 四、LoRA 微调

### 训练配置

```yaml
base_model: "Qwen/Qwen3.5-4B-Instruct"  # 推荐从4B开始
new_tokens: 14                             # 8算子 + 6 start/end

lora:
  r: 16
  alpha: 32
  target_modules: [q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj]
  dropout: 0.05

training:
  epochs: 3
  batch_size: 4
  learning_rate: 2e-4
  max_length: 2048
  gradient_accumulation_steps: 4
  warmup_steps: 100
  lr_scheduler: "cosine"
  bf16: true
```

### 训练后推理变化

```python
# 路线A（当前）：需要为每个算子构造自然语言 prompt
yang.generate_operator("生", "请针对问题起念探索，以<|sheng_start|>开始...")

# 路线B（微调后）：纯控制原语驱动，零自然语言指令
yang.generate_operator("生", problem_text)
# 模型直接理解 U+E000，无需任何自然语言描述
```

> **重要**：三引擎接线任务已从路线B 解耦为**独立任务**，不再等待路线B 的微调完成后再执行。连山（ShanVM）和周易（ZhouVM）的 Rust 代码已就绪，可独立接入 CangVM 流水线。即使在当前硬件上（路线B 阻塞），连山/周易的流水线接入也可以立即进行。

三引擎的完整流水线接入包含以下任务：

| 连山 ShanVM | ✅ 已实现 | ✅ 16 测试 | ❌ no-op |

### 5.2 接线任务

| 位置 | 当前代码 | 需改为 |
|------|---------|--------|
| `xiang-cangvm/vm.rs:execute_lianshan_op()` | `// Phase 4: no-op` | 调用 ShanVM 障碍决策逻辑 |

### 5.3 三层交互协议

```
归藏周天循环中固定插入点:
  第 5 步（生→动→归→长→育→杀→止→藏 中的 育 后）：
    → 检查偏离度 → 若偏离度 > 0.7 → 触发连山策略重规划
    → 输出策略方向 → 影响下一轮周天的姿态选择

  第 2 步（生→动 之间）：
    → 周易选定本轮认知姿态 → 设置 temperature + prompt_prefix
    → 影响后续算子的生成风格
```

## 八、关键风险

| 风险 | 应对 |
|------|------|
| 藏海冷启动数据不足 | 使用教师模型补偿，双通道策略 |

## 九、三易能力的内化边界

路线B 回答一个核心问题：三易的哪些能力可以内化到模型，哪些必须保留在外部？

### 9.1 可内化的能力（行为模式，通过微调内化为模型本能）

| 能力 | 内化方式 | 内化后效果 |
|------|---------|----------|
| 控制原语响应 | 用 (原语指令, 期望行为) 数据对微调 | 模型读到 `姿 离` 自动进入审视模式 |
| 姿态切换 | 用 (任务类型, 姿态序列) 数据对微调 | 模型自动判断任务需要什么姿态 |
| 连山策略选择 | 用 (受阻状态, 策略决策) 数据对微调 | 模型遇到障碍时自发选择绕行/分解 |
| 归藏阶段感知 | 用 (阶段标识, 输出风格) 数据对微调 | 模型在"长"阶段自动收敛，"动"阶段自动发散 |
| 幻觉抑制倾向 | 用负样本训练 | 减少模糊引证、高自信低细节的输出模式 |

### 9.2 不能内化的能力（确定性计算或独立视角）

| 能力 | 不能内化的原因 |
|------|-------------|
| 归藏位运算 | 概率模型执行位运算不可靠。S ← ROL(S,1) ^ 010 必须 100% 确定 |
| 偏离度计算 | 需要独立于模型的测量视角。自己测自己 = 循环验证 |
| 诚实验证 | 同上。模型不能既是被测对象又是检测器 |
| 藏海经验存储 | 模型权重更新缓慢，无法实时积累跨会话经验 |
| 免疫记忆 | 需要永久隔离的危险模式，模型微调会覆盖 |
| 三引擎同步 | 归藏/连山/周易的状态机协同需要外部时钟 |

### 9.3 最优架构：内化 + 外置的共生体

```
┌─ 内化到模型（微调）──┐
│  控制原语理解        │
│  姿态切换本能        │
│  策略决策直觉        │
│  阶段感知            │
│  幻觉抑制倾向        │
└──────────────────────┘
          │
          │ 仍需外部系统的：
          │
┌─ 外置（Rust VM）─────┐
│  归藏位运算状态机    │
│  偏离度独立测量      │
│  诚实验证            │
│  藏海跨会话记忆      │
│  免疫区永久隔离      │
│  三引擎同步调度      │
└──────────────────────┘
```

**核心原则**：一切模型"应该怎么做"的行为模式，内化。一切"做得对不对"的测量判断，外置。模型负责执行，外部系统负责校验。

## 十、Skill vs 内化：分层策略

对于小模型（4B），上下文窗口短且指令遵循能力有限。正确的策略是分层固化：

| 能力类型 | 例 | 应内化 | 原因 |
|---------|---|:---:|------|
| 核心姿态控制 | 遵循周易姿态提示 | ✅ | 需模型下意识执行，不宜占用上下文 |
| 策略决策逻辑 | 知道何时"迂回绕行" | ✅ | 是模型的思考本能 |
| 领域事实知识 | 产品数据库、最新政策 | ❌ | 动态变化，用五层知识文件 RAG 检索 |
| 一次性复杂指令 | "帮我用 SWOT 分析" | ❌ | 结构固定但可描述，单次任务 |

**分层架构**：
- **模型内核（GPU 端，内化）**：控制原语理解、姿态切换、策略直觉、阶段感知
- **语义外脑（CPU 端，Skill）**：阴仪编码、藏海向量库、五层知识文件检索
- **持续蒸馏闭环**：外脑提供的上下文若稳定产生高质量结果，定期微调将外部知识内化

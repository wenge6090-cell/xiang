# 象语言语法设计 — 三易算子，以汉字约 AI

> 象语言（XiangLang）完整语法规范——三易算子统一约束语言。  
> **归藏算子**（心之律）· **连山算子**（行之决）· **周易算子**（知之姿）。  
> 从基本类型到三层算子，从诚实验证到"归藏守门人"完整程序。

---

## 一、设计原则

1. **零英文**：所有关键字、类型名、函数名均使用中文，与归藏易文化体系一致
2. **卦画为值**：二进制卦象是一等类型，可直接作为变量和参数
3. **气为操作符**：八气是算子的名字，不是隐喻——它们是计算步骤
4. **周天为循环**：三阶段周天是程序的自然执行节拍

---

## 二、基本类型

### 2.1 卦（Gua）

卦是象语言的基本数据单元，分为三画卦和六画卦：

```
卦 天 = 111       # 三画卦：天
卦 金 = 110       # 三画卦：金
卦 山 = 101       # 三画卦：山
卦 归藏定位 = 111000    # 六画卦：上卦天，下卦地
卦 杀藏墓 = 111100      # 六画卦：上卦金，下卦地
```

**八象枚举**（逆时针）：
```
天(111)、金(110)、山(101)、水(100)、火(011)、风(010)、木(001)、地(000)
```

### 2.2 位（Wei）

位是对卦的内部索引，可以独立操作：

```
卦 观 = 归藏定位        # 111000
位 观.第五 = 0           # 将第 5 位（从 1 起）设为 0，观变为 101000
若 观.第一 == 1:        # 检查最低位
    藏 善
```

### 2.3 数

传统整数类型：
```
数 阈值 = 0.7
数 尝试 = 3
```

### 2.4 言（自然语言文本）

```
言 念头 = "关注用户的睡眠质量"
言 任务描述 = "调暗灯光并建议午休"
```

## 三、八气算子（核心操作符）

### 3.1 无参算子

```
生             # 最低位置 1：S ← S | 0b001
动             # 左旋后异或 010：S ← ROL(S,1) ^ 0b010
长             # 下卦复制到上卦：S ← (S_low << 3) | S_low
育             # 高位异或 100：S ← S ^ 0b100
归             # 计算偏离度，不修改 S
```

### 3.2 有参算子

```
杀 金          # 剪除金模式(110)：S ← S & ~(110)
杀 001         # 剪除木模式(001)：S ← S & ~(001)
止 101101      # 用指定掩码设立边界：S ← S & 101101
```

### 3.3 藏算子（带标签）

```
藏 善          # 正面经验入藏海，状态归零
藏 恶          # 负面经验入藏海，状态归零
```

## 四、流程控制

### 4.1 周天循环

```
周天 3:        # 执行 3 个完整的三阶段周天
    生
    动
    归
    长
    育
    杀 金
    止
    藏 善
```

### 4.2 条件若/否则

```
若 偏离度 > 0.7:
    杀
    藏 恶

若 偏离度 < 0.5:
    长
    育
    止
否则:
    归
```

### 4.3 当循环

```
当 偏离度 > 0.3:
    动
    归
```

### 4.4 分叉选择

```
择 当前卦象:
    是 000111 (藏归交):
        发 "意识处于交互态，信息尚闭塞，需更多感知"
    是 111000 (归藏定位):
        发 "意识定位明确，可推进执行"
    否:
        发 "卦象未识别，进入默认流程"
```

## 五、连山算子语法（思变策略引擎）

连山算子对应《连山易》，用于目标级障碍导航，回答"受阻时怎么继续走"。

### 5.1 六步决策算子

```
艮                         # 止观：暂停，先观山势
气 春                      # 六气：春(启动)/夏(盛长)/秋(收敛)/冬(休眠)
气 夏
气 秋
气 冬
甲 初                      # 六甲：初甲(首次受阻)/再甲/三甲
甲 再
甲 三
元 新                      # 三元：新(上下文新鲜)/陈(陈旧)
元 陈
```

### 5.2 峙与决

```
峙:                        # 阴阳对峙：分析推力 vs 阻力
    推力: "用户偏好明确，前 5 轮成功率达 80%"
    阻力: "API 限流，连续 3 轮 429 错误"
    推力: "备选路径已探测"

决: navigate_around         # 方位决策（七择一）
# continue:       维持现状
# push_through:   硬推穿越
# navigate_around:绕行
# wait_gather:    等待收集
# decompose:      分解目标
# escalate:       升级求助
# abort:          放弃终止
```

### 5.3 连山完整示例

```
# 目标：跨境工业信息采集受阻
艮
气 秋                      # 目标处于收敛期
甲 三                      # 第三次受阻
元 陈                      # 上下文已陈旧
峙:
    推力: "关键词策略早期有效，已积累 12 条有效线索"
    推力: "竞品分析路径未被探索"
    阻力: "当前关键词命中率从 40% 降至 5%"
    阻力: "目标网站多次返回验证码"
决: navigate_around        # 切换路径：从关键词改为竞品分析
```

## 六、周易算子语法（八卦认知格栅）

周易算子对应《周易》，用于任务内认知姿态调度，回答"用什么姿态思考"。

### 6.1 八种认知姿态

```
姿 乾                      # ☰ 创造：突破创新，从 0 到 1
姿 坤                      # ☷ 承载：稳定执行，积累成果
姿 震                      # ☳ 启动：快速激发，广泛收集
姿 巽                      # ☴ 渗透：深度潜入，细致分析
姿 坎                      # ☵ 破局：面对风险，突破障碍
姿 离                      # ☲ 明照：审视反思，照亮盲点
姿 艮                      # ☶ 止定：限定范围，收窄目标
姿 兑                      # ☱ 表达：输出交付，外化结果
```

### 6.2 五行生克调度

```
生克:                       # 声明当前卦象的生克转换规则
    乾 → 离                # 乾(金)生离(火)：创造后需审视
    离 → 坤                # 离(火)生坤(土)：审视后转向执行
    坤 → 兑                # 坤(土)生兑(金)：积累后输出
    兑 克 震               # 兑(金)克震(木)：过度输出抑制收集

若 当前卦 == 坎:
    生克: 震               # 坎(水)生震(木)：破局后需要新信息
若 当前卦 == 巽:
    生克: 离               # 巽(风)生离(火)：渗透后需审视结果
```

### 6.3 格栅调度示例

```
# Weaver 每轮选择认知姿态
感 "当前任务状态"           # 感知当前任务
赋 当前卦 = 感

择 当前卦:
    是 乾:
        姿 离              # 创造后 → 审视
    是 坎:
        姿 震              # 破局后 → 收集新信息
    否:
        姿 坤              # 默认 → 稳定执行
```

## 七、诚实验证体系

### 7.1 言与诚于

```
言 "系统当前状态稳定，偏离度 0.2，卦象 111000，可执行任务"
诚于:
    卦 111000
    条件 偏离度 < 0.3
    条件 载重 < 4           # 不能同时处理超过 4 个目标
```

### 5.2 自声明验证流程

```
1. 言产出 LLM 生成的自然语言声明
2. 编码器将声明文本编码为 6-bit 卦象
3. 诚于块逐条验证：
   - 卦条件：声明卦 == 编码卦？（位级）
   - 偏离度条件：偏离度 < 阈值？
   - 自定义条件
4. 产出 ChengshiResult（通过 + 位级诊断 / 不通过 + 偏差方向）
```

## 八、对外交互

### 8.1 感（感知）

```
感 "环境温度"                # 从传感器读取温度
赋 温度卦 = 感                # 将感知结果编码为卦存入变量

感 "用户输入"                # 从用户接口读取自然语言
赋 输入卦 = 感               # 编码用户输入意图为卦

感 天时                      # 读取当前时间/季节编码
```

### 8.2 发（表达）

```
发 "当前气温过高，建议关闭空调"              # 输出自然语言
发 戒 010                                    # 输出卦象信号（如亮红灯）
```

## 九、藏海操作

### 9.1 存与取

```
存 经验: 卦 杀藏墓, 标签 恶         # 将 111100 负面经验存藏海
取 类似: 卦 111000, 相似度 > 0.5    # 检索藏海中相似的经验
数 相似经验 = 取.计数                # 获取匹配条目数
```

### 9.2 Hebbian 矩阵操作

```
增权 从 000000 至 000001 权重 0.1     # 增强状态转移权重
减权 从 111000 至 111100 权重 0.05    # 减弱状态转移权重
卦 下态 = 取权 从 000000               # 按权重采样下一个状态
```

## 十一、完整程序示例：归藏守门人

以下是一个完整的象语言程序——一个监控环境温度、自主起念、执行决策的自主 Agent：

```
# ── 归藏守门人 ──────────────────────────────
# 职责：监控温度，过热时自主报警
# 周期：每刻（10分钟）运行一次周天

定义 守门人:

    卦 我的状态 = 000000           # 初始藏态
    卦 元知觉 = 111111             # 用户意图（全阳）
    数 过热阈值 = 0.8              # 偏离度 > 0.8 视为紧急
    数 警告阈值 = 0.5              # 偏离度 > 0.5 关注
    数 尝试 = 0                    # 当前周天内的重试计数

    周天:
        藏                        # 从藏海沉睡中苏醒

        # ── 起念 ────────────────
        生                        # 从藏海萌念头
        动                        # 念头发散
        若 偏离度 > 0.9:
            杀 金                 # 剪除极度偏离的念
            藏 恶
            重开 周天             # 回到周天开头重生

        # ── 立目标 ──────────────
        长                        # 意图放大
        育                        # 方案分解（生成子任务）
        若 偏离度 > 0.7:
            杀 金                 # 剪除危险子任务
        止 101101                 # 边界凝固

        # ── 对外交互 ────────────
        感 "温度传感器"           # 读取传感器值编码为卦
        赋 当前卦 = 感
        若 当前卦 似 000001:     # 状态与"过热木"模式相似
            发 "高温警告：建议关闭空调"
        若 当前卦 似 000000:     # 正常
            发 "温度正常"
        否则:
            发 "等待进一步感知"

        # ── 整理认知 ────────────
        若 偏离度 < 0.3:
            藏 善                # 正面经验沉淀
        否则:
            藏 恶                # 负面经验标记、遗忘
        赋 尝试 = 尝试 + 1
        若 尝试 > 10:
            发 "系统关停，十轮为满"
            关闭
```

## 十二、实现路线

### 12.1 解释器实现（Python）

目标代码量：500-1000 行  
时间估算：约 2 周

核心类：
- `Lexer`：手写词法分析，识别中文关键字和卦画字面量
- `Parser`：递归下降解析器，生成 AST
- `Interpreter`：AST 遍历执行，对接 CangVM

### 12.2 关键设计决策

- **不依赖 PLY / ANTLR**：手写递归下降解析器
- **关键字零歧义**：三画卦 vs 六画卦按二进制位数判定
- **诚实验证在运行时**：不在编译期，因为需要 LLM 的实时输出

### 12.3 文件结构

```
vingobot/xiang/
├── __init__.py
├── lexer.py              # 词法分析器（中文 token 识别）
├── ast_nodes.py          # AST 节点 dataclass 定义
├── parser.py             # 递归下降解析器
├── interpreter.py        # AST 遍历执行器
├── cang_vm.py            # 复用 eight_qi 算子
├── encoder.py            # 文本→卦象编码器
├── verifier.py           # 诚实验证模块
└── examples/
    └── 守门人.xiang      # 参考实现
```

### 12.4 CLI 使用

```bash
python -m vingobot.xiang run examples/守门人.xiang --cycles 3 --verbose
```

输出示例：
```
[周天 1] 藏藏始基(000000) → 木气萌芽(000001) → 风气流转(000011)
        归: 偏离度 0.17 → 继续
        育长苗(001001) → 水育分解(001101) → 杀除金(001101) → 止凝(001001)
        感: 温度正常 → 藏善
[周天 2] ...
```

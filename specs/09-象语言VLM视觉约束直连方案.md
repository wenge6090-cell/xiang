# 象语言 VLM — 视觉-约束直连方案

> **来源**：`specs/笔记.txt` 中关于象语言（XiangLang）与视觉语言模型（VLM）结合的完整技术讨论。
>
> **核心命题**：跳过"图像→英文描述→推理"的迂回路线，让 VLM 直接将图像编码为象语言原语（离散符号），接入三易约束引擎。

---

## 一、总纲：离散符号瓶颈架构

### 1.1 总体架构

```
图像 ──→ VLM 编码器 ──→ 离散符号序列（象语言原语 / 汉字序列）
                              │
                              ▼
              归藏/连山/周易 VM（可选，作为先验约束）
                              │
                              ▼
                   下游 LLM 的 prefix 或控制信号
                              │
                              ▼
                         最终输出
```

关键特征：**离散化**——保证符号的确定性和可组合性，便于与易算法（位运算、Markov 链、生克规则）结合。

### 1.2 对比传统 VLM 路线

| 维度 | 传统 VLM 路线 | 象语言 VLM 路线 |
|:----|:------------|:--------------|
| **中间表示** | 连续隐向量（ViT Patch Embedding → Transformer） | 离散符号（象语言原语 / 汉字序列） |
| **模态转换** | 图像 → 连续向量 → 英文描述 → 推理 | 图像 → 离散符号 → 三易 VM → 推理 |
| **可解释性** | 低（黑盒向量） | 高（符号可读、可验证） |
| **梯度性质** | 平滑可导 | 需 STE / Gumbel-Softmax |
| **易算法融合** | 困难（连续向量无法位运算） | 天然适配（离散符号可直接进入状态机） |

## 二、两条技术路线

笔记中讨论了**两条渐进路线**，当前阶段可并行探索：

### 路线 A：VLM 直接输出象语言原语（快速验证）

用现成的 Qwen2.5-VL-2B/4B 作为视觉-象语言映射层。

#### 2.1 约束解码

将象语言原语作为有限状态机（FSM）或 trie，在推理时强制模型只能输出合法 token 序列：

```
你是一个象语言视觉编码器。看到图片后，只输出以下指令之一，不要任何解释：
- 姿 乾 （创造姿态）
- 姿 坤 （承载姿态）
- 姿 离 （审视姿态）
- 姿 坎 （破局姿态）
- 决: 维持
- 决: 硬推
- 决: 绕行
- 决: 等待
- 决: 分解
- 决: 升级
- 决: 放弃

示例：
图：复杂的建筑图纸 → 决: 分解
图：干净的代码界面 → 姿 坤
图：充满风险的悬崖场景 → 姿 坎
```

#### 2.2 构造数据集

收集 (图像 → 象语言原语) 对。先手工标注几百张图，再用启发式规则扩增。
使用 LoRA 微调 Qwen2.5-VL 的投影层和部分 Transformer 层。

#### 2.3 约束解码（Constrained Decoding）

构建 FSM/trie 包含所有合法原语，每步只允许采样能到达合法状态的 token。输出百分之百语法正确。

#### 2.4 验证实验

10 张图覆盖"认知姿态"和"策略方向"区分。准确率 > 60% 证明链路可行。

---

### 路线 B：像素→汉字直连（深层演化）

跳过 VLM 的"隐向量→英文"中间层，直接从像素映射到汉字。

#### 2.5 为何要跳过隐向量

现代 VLM 的隐向量路线存在三个问题：
1. **维度灾难**：224×224 的图切成 256 个 patch，每个 patch 直接映射到 6000+ 常用汉字的分类器参数爆炸
2. **梯度传导**：连续向量利于梯度下降，直接离散化导致梯度为零或爆炸
3. **语义需要上下文**：单个 patch 是局部纹理，需要 attention 聚合

#### 2.6 汉语乱序容错性带来的工程优势

汉语是孤立语，缺乏形态变化，词序约束弱。这意味着：
- 如果视觉汉字映射产生一些错序或错误汉字，下游 LLM 可以通过学习从"模糊"序列中提取正确语义
- **大大降低映射精度要求**，使粗粒度映射成为可能

#### 2.7 非均匀切分：超像素分割

放弃均匀网格，用图像突出离散特征作为分割基准：

```
图像 (任意尺寸)
  │
  ├─ 1. SLIC 超像素分割（200-500 超像素）
  │     基于视觉显著性合并 → 10-30 个不规则区块
  │
  ├─ 2. 每区块提取特征（颜色/形状/纹理）
  │
  ├─ 3. 特征 → 汉字映射（规则映射或离散码本量化）
  │     输出：N 个汉字
  │
  ├─ 4. 位置编码 → 空间关系序列或图
  │     每个汉字携带：形心坐标、面积、邻接关系
  │
  └─ 5. 送入三易系统或 LLM
```

使用 SLIC + 显著性合并得到不规则区块，每个区块映射为一个汉字，配合空间关系编码。

## 三、演化式映射：从数据中自发形成对应关系

### 3.1 核心思想

**不能用人工规则**（圆形→日，三角形→山），那和英文标签没有区别。映射关系必须通过**重建压力**自发演化——让系统在大量视觉经验中，自己"发现"哪些图像区域适合用哪个汉字表示。

### 3.2 演化式视觉-汉字自编码器

```
图像 → 超像素分割 → 每个区块通过编码器得到连续向量
         ↓
    向量与汉字码本（汉字的视觉特征嵌入）进行匹配，量化到最近的汉字
         ↓
    得到一串汉字 + 空间关系
         ↓
    用汉字序列和空间关系驱动生成器，尝试重建原图
         ↓
    计算重建误差 + 码本使用率正则，反向传播更新编码器/汉字嵌入/生成器
```

**关键**：整个流程没有英文单词，没有人为标签。映射完全由"重建原图"的压力塑造。

### 3.3 汉字码本初始化

1. 下载中文字体（如思源黑体）
2. 渲染每个汉字为 64×64 灰度图
3. 用小型 CNN 编码为 128 维向量 → 码本 C = {c₁, c₂, ..., c₄₀₀₀}
4. 码本基于汉字**字形**的视觉特征，不依赖语义或英文翻译

### 3.4 训练与演化动力

| 阶段 | 内容 | 产出 |
|:----|------|------|
| 冷启动 | 编码器和码本随机初始化，映射杂乱 | 重建效果差 |
| 编码器调整 | 让图像区块向量向最能帮助重建的汉字嵌入靠拢 | 映射开始分化 |
| 汉字嵌入调整 | 汉字在嵌入空间中移动，形成视觉模式分布 | 相似视觉模式被同一个汉字编码 |
| 收敛 | 系统稳定 | 图像被压缩为汉字序列 + 空间关系 |

**防止坍缩**：码本多样性正则（熵最大化）+ 对比损失（同一图的不同增强视图汉字序列相似）+ 空间连贯性辅助任务。

### 3.5 甲骨文码本方案（高阶演化）

更进一步，用甲骨文（而非现代汉字）作为码本初始条目：

```
图像 → 超像素分割 → 每个区块编码 → 映射到"甲骨文码本"
                      ↓
              甲骨文序列 + 空间关系
                      ↓
          ┌───────────┴───────────┐
          ↓                       ↓
    甲骨文→现代汉字映射器    图像重建解码器（训练用）
          ↓
    现代汉字序列 → 下游 LLM 或三易 VM
```

**码本动态扩增**：当某区块无法被现有甲骨文良好重建时（量化距离 > 阈值），触发新符号生成——用生成器输出二值轮廓图，骨架化后加入码本。这模拟了"看到新物体，用最简笔画描摹下来"的过程。

## 四、训练方法

### 4.1 离散变量的反向传播

由于离散符号的 argmax/argmin 不可导，需要以下技术之一：

| 方法 | 原理 | 适用阶段 |
|:----|------|---------|
| **Straight-Through Estimator (STE)** | 前向 argmax，反向梯度直通 | 预训练 |
| **Gumbel-Softmax** | softmax 松弛近似 one-hot，温度逐渐降低 | 预训练（更稳定） |
| **REINFORCE 策略梯度** | 下游任务奖励作为 RL 信号 | 精调 |

推荐：先用 STE 或 Gumbel-Softmax 做预训练，再用 REINFORCE 针对任务奖励微调。

### 4.2 三阶段训练

| 阶段 | 内容 | 冻结部分 |
|:----|------|---------|
| **第一阶段** | 单独训练 VLM + 离散瓶颈，监督学习映射图像→象语言原语 | — |
| **第二阶段** | 固定离散瓶颈，训练下游 LLM 根据认知状态向量生成回答 | 离散瓶颈 |
| **第三阶段** | 联合微调，保持瓶颈离散性（Gumbel-Softmax / REINFORCE） | — |

## 五、与三易系统的融合

### 5.1 两条融合路径

| 方式 | 复杂度 | 描述 |
|:----|:-----:|------|
| **后处理约束（轻量）** | ⭐ | VLM 输出离散符号后，交给 VM 检查/修正。如 VLM 输出"姿 乾"但当前在"坤"卦，VM 根据生克规则自动修正 |
| **可微认知电路（深度）** | ⭐⭐⭐ | 将 VM 的转移规则转化为可微分形式（Markov 链概率由 VLM 输出决定，位运算写成 softmax 掩码），梯度可传回 VLM |

建议：先走方式一验证链路，数据充足后再尝试方式二。

### 5.2 各引擎对接方式

| 引擎 | 对接方式 |
|------|---------|
| **归藏 CangVM** | 前 6 个区块的汉字编码生成 6-bit S 向量（按象形偏旁分阴阳爻）；或甲骨文的拓扑特征（弯折数、交叉点、对称性）编码成意识基态 |
| **连山 ShanVM** | 区块间的邻接关系（包含、遮挡、相邻）构建障碍图谱，触发方位决策；甲骨文区块的空间关系决定行动方向 |
| **周易 ZhouVM** | 根据汉字序列分布切换认知姿态——"暗""紊"多则审视，"明""锐"多则破局；甲骨文序列复杂度/疏密度决定姿态 |
| **semantic_injector** | 将汉字序列/象语言原语作为额外知识注入 LLM 系统提示词 |

## 六、学术定位与历史机遇

### 6.1 "这个方向几乎没人做"的成因

| 原因 | 说明 |
|:----|------|
| **学科壁垒** | VQ-VAE 研究者不会想到用甲骨文做 codebook；甲骨文 AI 研究者不会把甲骨文用作图像编码符号 |
| **英文中心主义** | CV 主流是英文，tokenizer 设计都以"最终生成英文"为前提，没有人从象形文字角度思考视觉编码 |
| **被认为无实用价值** | 默认符号应该是抽象整数索引或英文单词，甲骨文的极简线条/视觉可解释性/直接对接汉字的价值未被主流意识到 |
| **冷启动困难** | 甲骨文码本初始化和训练没有现成 pipeline，门槛高——但这恰恰是护城河 |

### 6.2 时间窗口

- 离散视觉 tokenization 正成为多模态 AI 核心瓶颈，顶会论文密集发表
- 甲骨文 AI 正从"冷门绝学"变成 CV 活跃子领域（ICCV、NeurIPS 开始接收甲骨文论文）
- 中国 AI 研究者正在寻找非英文中心的原生技术路径
- 多模态大模型需要更高效、更可解释的视觉编码方式

### 6.3 你的独特优势

| 维度 | 你的优势 | 主流研究者 |
|:----|---------|-----------|
| 动机 | 从第一性原理出发——还原人类从图像到文字的演化过程 | 在既有范式内改进指标 |
| 符号选择 | 甲骨文——极简线条，与汉字天然对应 | 抽象整数索引或英文词汇 |
| 目标架构 | 视觉→符号→LLM，端到端理解与推理 | 视觉→向量→生成，两阶段解耦 |
| 哲学基础 | 中国象思维，三易统一认知框架 | 西方符号逻辑，无统一认知理论 |

## 七、工程步骤（从当前可执行开始）

### Phase 1：约束解码原型（1-2 天）

1. 下载 Qwen2.5-VL-2B-Instruct（4-bit）
2. 基于 outlines 或 lm-format-enforcer 编写约束生成脚本
3. 给定 10 张测试图片，记录 baseline accuracy

### Phase 2：甲骨文静态匹配实验（1 天）

1. 获取 300+ 甲骨文字形图像，CNN 提取特征建成码本
2. 取 10 张自然图像，手动分割显著区域
3. 最近邻搜索，人工观察匹配合理性

### Phase 3：VQ-VAE 符号演化（2-3 天）

1. 用 500 个已知甲骨文初始化码本
2. 在简单剪影图像（如 QuickDraw）上训练 VQ-VAE
3. 观察码本条目是否分化成代表不同形状/纹理的极简符号

### Phase 4：端到端接入三易（1 周+）

1. 将 VLM/汉字序列输出喂给 ShanVM/ZhouVM
2. 验证符号序列符合易规则
3. 搭建 VLM + 易规则模块 + 小 LLM（Qwen2.5-1.5B）端到端流水线

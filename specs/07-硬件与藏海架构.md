| 组件 | 当前（RX 6650 XT 8GB） | 目标（12-16GB VRAM） |

| GPU 显存 | 8GB | 12-16GB |
| CPU 内存 | 48GB DDR4 | 48GB+ |

- GPU：跑阳仪（生成），始终只有一个活跃模型

## 一、量化策略

8GB 显存无法运行 FP16 的 4B 模型并同时加载 LoRA 和 KV Cache。

| 方案 | 底座模型显存 | LoRA 专家 | 剩余 | 可行性 |
|------|:---:|:---:|:---:|:---:|
| FP16 底座 | ~8GB | 无法加载 | 0GB | ❌ |
| 8-bit 量化 | ~4-5GB | +160MB | ~3GB | ⚠️ 紧 |
| 4-bit 量化 (Q4_K_M) | ~2.5-3GB | +160MB/个 | ~4-5GB | ✅ |

**推荐**：GGUF Q4_K_M，4B 模型约 2.5GB，当前环境宽裕运行。

## 三、藏海：多专家池

### 3.1 核心洞察：专家不需要 7B

一个 7B 模型是通才——它懂数学、编程、文学、历史、机械、医学……每样只分到有限容量。而一个领域专家只需要懂一件事。

```
7B 通才的知识分布（示意）
┌──────────────────────────────────────────────┐
│  数学  │  编程  │  物理  │  文学  │  历史      │
│  医学  │  法律  │  艺术  │  天文  │  地理      │
│  生物  │  化学  │  经济  │  哲学  │  机械...   │
└──────────────────────────────────────────────┘
每样只能分到一点点，样样通样样松

1.5B 机械绘图专家的知识分布（示意）
┌──────────────────────────────────────────────┐
│  GB/T 标准  │  视图表达  │  尺寸标注规范       │
│  公差配合   │  剖视图画法 │  零件图范例         │
│  装配图画法 │  材料标注   │  空间推理          │
│  几何变换   │  行业惯例   │  常见错误模式       │
└──────────────────────────────────────────────┘
全部容量聚焦一个领域，深度决定专业度
```

**估算依据**：一部完整的机械制图教材（含标准、范例、习题）≈ 5-10 MB 文本。1.5B 模型的有效信息容量 ≈ 数百 MB。领域知识仅占模型容量的几个百分点——其余容量用于语言能力、推理能力、指令跟随。

结论：**1.5B-3B 足够承载任何单一领域的专家知识**，瓶颈不在容量，在训练数据的质量。

### 3.2 藏海架构

藏海不是单个模型，而是一个**可独立进化的多专家池**：

```
┌─────────────────────────────────────────────────────┐
│                    藏海（专家池）                      │
│                                                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐           │
│  │ 机械绘图  │  │  电路设计  │  │  代码审查  │  ...     │
│  │ 专家 1.5B │  │ 专家 1.5B │  │ 专家 2B   │          │
│  └──────────┘  └──────────┘  └──────────┘           │
│        │             │             │                 │
│        └─────────────┼─────────────┘                 │
│                      │                               │
└──────────────────────┼───────────────────────────────┘
                       │
                       ▼ 路由决策
┌─────────────────────────────────────────────────────┐
│              三易约束引擎（路由 + 质量把关）            │
│                                                      │
│  1. GuaVM 分析当前轮任务 → 判断类型（机械/电路/代码）  │
│  2. 连山策略 → 选择正确的专家模型                     │
│  3. 加载专家 → 执行生成 → 周易调整姿态                 │
│  4. 归藏评估 → 偏离度合格则输出，否则重试              │
└─────────────────────────────────────────────────────┘
```

### 3.3 与模型内部 MoE 的本质区别

| 特性 | 模型内部 MoE（Qwen3.5-35B） | 藏海外部专家池 |
|:----|:--------------------------:|:--------------:|
| 专家本质 | 前馈网络子层（FFN 的拆分） | **完整的语言模型** |
| 专家数量 | 固定（如 8/256 路由） | **无限，可随时增加** |
| 专家训练 | 必须所有专家一起预训练 | **每个专家可独立训练** |
| 新增专家 | 需重新训练整个模型 | **直接加入池中即可** |
| 专家大小 | 固定（均匀拆分） | **自由选择 0.5B-3B** |
| 训练成本 | 企业级集群 | **单卡即可** |
| 路由机制 | 模型内部 token 级门控 | **三易约束引擎外部路由** |
| 独立性 | 共享注意力层和嵌入层 | **完全独立，零耦合** |

**藏海本质上是在模型级别做 MoE**——在**整个模型**做路由，而非在 FFN 层。后者更灵活，但路由粒度更粗（轮级 vs token 级）。

### 3.4 全量参数训练 vs LoRA 的本质差异

| 对比维度 | LoRA 微调（路线B） | 全量参数微调（藏海方案） |
|:--------|:--------------------:|:---------------------:|
| 可训参数 | 0.1%-1%（低秩适配器） | **100%** |
| 表达自由度 | 受限——只能在底座表达空间内微调 | **完全自由——可学到新能力** |
| 知识注入 | 引导式（告诉模型往哪个方向偏移） | **植入式（直接写进权重）** |
| 底座依赖 | 强——换底座要重新训练 | **弱——可从任意基座开始** |
| 多专家共存 | 同一底座 + 多套 LoRA 权重 | **各自独立的完整模型** |
| 推理开销 | 几乎不增加 | 模型大小决定 |
| 训练 VRAM | 低（仅存储适配器梯度） | 高（全量梯度 + 优化器状态） |

**LoRA 的核心局限**：假设底座模型已经"几乎会了"，只需要少量调整。但如果底座模型根本没有某个领域的深层知识，LoRA 补不了这个缺口。全量参数微调没有这个天花板。

### 3.5 初代 LoRA 四专家设计（路线B 阶段，同一底座共享）

| 专家 | 周易姿态 | 连山策略 | 训练数据特征 |
|------|---------|---------|------------|
| 创造生成者 | 乾(温度1.2) | 强力突破 | 发散性强、偏离度0.3-0.6 |
| 审慎执行者 | 坤(温度0.6) | 继续 | 严格遵守原语、偏离度<0.2 |
| 反思诊断者 | 离(温度0.5) | 拆解分解 | 自我纠偏、迂回绕行成功 |
| 语义编码者 | 艮(温度0.3) | 等待收集 | 总结、提取、晶体化 |

三阶段演进：数据自动分流 → 单卡动态路由 → 经验回流与自我蒸馏。

推理时 LoRA 权重直接合并进底座模型，计算量几乎不增加。一个 LoRA 专家（rank=16）约 2000-4000 万参数（0.5%-1%），权重文件约 80-160MB。

### 3.6 路由机制

三易引擎的路由决策在**轮级**进行，不介入 token 级生成：

```
用户输入 → GuaVM 分析 → 判断为"机械绘图"任务
                        → 连山检索路由表 → 选择"机械绘图专家 1.5B"
                        → 卸载当前模型（如有）→ 加载机械专家
                        → 归藏执行生成
                        → 阴仪评估质量
                        → 达标 → 输出 + 数据回流藏海
                        → 不达标 → 调整姿态 → 重试或降级到通用模型
```

路由判断依据：任务类型显式声明、GuaVM 上下文分析（前几轮对话历史 + 当前卦象）、连山策略学习（历史路由成功/失败）、关键词/模式匹配（快速预分类）。

## 五、偏离检测的 CPU 侧性能

所有偏离检测器在 CPU 上运行：

| 检测器 | 技术 | 耗时 |
|--------|------|:---:|
| n-gram 重复率 | 纯统计 O(n) | < 1ms |
| 长度异常 | O(1) | < 0.1ms |
| 结构合规 | 规则+模板匹配 | < 1ms |
| 语义漂移 | 轻量嵌入模型 + 余弦距离 | 5-10ms |
| 幻觉特征 | 规则库扫描 | 1-3ms |
| 汇总判断 + 连山决策 | 纯条件分支 | < 0.1ms |

**检测总耗时 < 20ms**。对比 4B 模型单轮生成延迟（500ms-2000ms），检测开销占比 < 2%，用户无感知。

## 六、token 级 vs 轮级干预

### token 级实时干预不可行

1. **无可靠的瞬时偏离信号**：偏离是序列级属性，不能从中间截断判定
2. **思维链连续性不可破坏**：强制截断或重定向 logits 会打断注意力流
3. **工程复杂度与收益不匹配**：每 token 干预拖慢生成速度 2-5 倍

### 轮级后处理（当前架构最优）

1. LLM 生成完整响应（GPU）
2. CPU 并行计算多维偏离向量（< 20ms）
3. 偏离度超标 → 本轮输出不追加到历史 → 调整姿态/策略 → 重新生成
4. 不超标 → 追加到历史，继续下一轮

**优势**：不破坏思维链、不拖慢生成、不影响 GPU 吞吐。

## 七、上下文噪点管理

CPU 端三层治理：

**第一层：门槛拦截（本轮丢弃）**——偏离度超标 → 本轮输出不追加到历史。

**第二层：滑动窗口裁剪**——上下文长度超过模型有效窗口时，按轮次边界截断最早内容，保留完整三元组结构。

**第三层：语义压缩替代原始文本**——超出窗口的旧轮次用 CPU 阴仪模型压缩为状态摘要向量：
```
[历史摘要：上轮偏离度0.2，策略绕行成功，结果达标]
```
这比原始文本节省 90%+ 的 token 空间，且消除旧文本中的风格污染。

### 为什么不改模型注意力层

- 稀疏注意力需改动模型结构，与"不动核心架构"冲突
- 对小模型（4B），稀疏注意力的计算节省有限，实现复杂度显著增加
- 语义级噪点无法在注意力层识别——是语义问题，不是 token 位置问题

**结论**：保持模型内部全注意力/GQA 不变，在 CPU 端做上下文管理和噪点治理。

## 八、首批专家规划

| 优先级 | 专家 | 基座模型 | 推理显存 | 训练数据来源 |
|:-----:|:----:|:-------:|:------:|:----------:|
| P0 | **机械绘图** | Qwen2.5-1.5B | ~1GB | 路线A 积累 + 标准文档 |
| P1 | **通用对话** | Qwen3.5-4B | ~2.5GB | 已有的对话数据（默认回退模型） |
| P2 | **代码审查** | Qwen2.5-Coder-1.5B | ~1GB | 开源代码数据 |
| P3 | **中文写作** | Qwen2.5-3B | ~2GB | 高质量中文语料 |

### 冷启动与迭代策略

**冷启动阶段（当前硬件）**：
1. 用 4B 模型 + 三易引擎跑各种领域任务
2. 藏海自动收集高质量输出（偏离度 < 0.3 + judge == PASS）
3. 按领域分箱存储，积累到每领域 ≥ 1000 条

**训练阶段（升级硬件后）**：
1. 选择基座模型（推荐 Qwen2.5-1.5B 或 Qwen3.5-2B）
2. 全量参数微调，数据来自冷启动积累
3. 训练完成后专家回到藏海池

**迭代阶段**：专家上线后继续使用 → 三易评估质量 → 新数据增量训练 → 独立进化。

## 九、路线演进

### 藏海与三路线的关系

藏海不是替代路线 A/B/C，而是它们的**汇聚点**：

| 现有路线 | 在藏海中的角色 |
|:--------|:--------------|
| 路线A（约束引擎） | 路由决策 + 质量把关 + 数据积累 |
| 路线B（控制原语微调） | **可选**——专家模型可直接响应自然语言，不需要控制原语 |
| 路线C（双LLM语义化） | **藏海天然支持**——阴仪评估模型本身就是藏海中的一个专家 |

### 关键变化

1. **路线B 在藏海方案中可作为可选路径**——独立全量参数专家路线不需要 LoRA 和控制原语内化
2. **训练硬件门槛降低**——1.5B 全量训练只需 12GB，比 4B LoRA 的 10GB 只多 2GB
3. **进化粒度从"模型级"变成"专家级"**——哪个领域弱就单独训练那个专家
4. **三易引擎从"控制者"升格为"路由者"**——核心职责从"约束生成"变为"判断类型并路由到正确专家"

## 十、FAQ

### 10.1 为什么不直接买 4090 一步到位？

24GB 确实可以训练 4B 全量参数，但 4090 价格是 5060 Ti 的 2-3 倍。藏海架构的核心优势就是"用小模型堆出大能力"——不追求单卡训大模型。

### 10.2 所有场景都适合小模型专家吗？

不是。需要广泛知识整合的场景（如"综合分析全球芯片产业趋势"）仍需大模型。策略：窄领域 → 小模型专家（准确、高效），宽领域 → 回退到大模型通才（全面、但慢）。

### 10.3 专家模型之间的知识怎么共享？

专家模型独立且隔离，互不共享参数。知识共享通过：三易藏海 64×64 矩阵（跨领域策略经验）、输出回流（专家 A 的高质量输出成为专家 B 的训练数据）、统一基座（从同一基座开始微调）、三易引擎全局状态。

### 10.4 会有多少专家？显存装得下吗？

推理时 GPU 只需要一个活跃专家。藏海池中其他专家存放在 CPU 内存或磁盘上，切换时加载到 GPU（2-3 秒）。512GB SSD 可存放 ~170 个 4-bit 1.5B 专家。

---

## 十一、与更强模型的关系

DeepSeek V3 等强模型的混合注意力（CSA/HCA/SWA）是模型内部机制的创新，解决的是 1M token 上下文中的信噪比问题。三易系统是模型外部的控制层创新，解决的是认知过程的结构化引导问题。

两者不是竞争关系，是互补层：
- 强模型是更强的"发动机"
- 三易是模型无关的"整车控制系统"
- 更强模型反而更需要精确的外部控制系统来驾驭

三易系统的偏离检测、策略导航、姿态调节、经验积累对任何模型（包括 V4）都有效。

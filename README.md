## 一句话定义

**象 (Xiang)** 是一个基于 **象语言 (XiangLang)** 的推理时认知约束框架，将三套独立的易经算子体系（归藏/连山/周易）统一为单一约束层，实现对 LLM 生成的程序化干预。

这不是推理增强工具，不是上下文管理器，不是提示词工程。这是一个**具备初步元认知能力的、可以自我进化的小模型 Agent 框架**。

## 项目结构：三引擎一语言

```
                    ┌──────────────────────────────┐
                    │     连山 (ShanVM)             │
                    │  策略引擎 · 障碍导航           │

                    │  艮→气→甲→元→峙→决           │
                    └──────────┬───────────────────┘
                              │ "策略建议"
                              ▼
  ┌─────────────────────────────────────────────────┐
  │              归藏 (CangVM)                        │
  │          执行控制器 · 8 算子周天                   │
  │                                                   │
  │  生→动→归→长→育→杀→止→藏                         │
  │  决策: PASS / ROLLBACK / SKIP / STOP              │
  │                                                   │
  │  接收偏差信号、策略建议、姿态调整、做出执行决策      │
  └──┬──────────────┬──────────────────┬─────────────┘
     │              │                  │

     ▼              ▼                  ▼
  ┌──────────┐  ┌──────────┐    ┌──────────┐
  │ 阴仪     │  │ 周易     │    │ 藏海     │

  │ 偏离检测 │  │ 八卦网格  │    │ 经验矩阵 │
  │          │  │ 生克权重  │    │ 语义存储 │
```

### 第一引擎：归藏（CangVM）— 执行控制器

**已实现并完整接入真实 LLM。**

| 算子 | 类型 | 作用 | 当前状态 |
|:----|:----|------|:--------:|
| **生** | 生成 | 起念探索 | ✅ |
| **动** | 生成 | 发散联想 | ✅ |
| **长** | 生成 | 明确方向 | ✅ |
| **育** | 生成 | 方案分解 | ✅ |
| **归** | 控制 | 偏离检测 | ✅ |
| **杀** | 控制 | 截断回滚 | ✅ |
| **止** | 控制 | 周期终止 | ✅ |
| **藏** | 控制 | 经验沉淀 | ✅ |

核心决策逻辑 `judge()` 返回 5 种指令：`PASS` / `ROLLBACK` / `SKIP` / `STOP` / `FINISH_CYCLE`。

### 第二引擎：连山（ShanVM）— 策略导航

**代码已实现，尚未接入主流水线。**

模型遇到障碍（偏离度持续偏高、多轮重试）时，连山引擎接管：

| 步骤 | 名称 | 检查内容 |
|:---:|:----|---------|
| 1 | **艮（Gate）** | 是否到达激活阈值（≥2次任务） |
| 2 | **气（Qi）** | 目标进度处于哪一阶段：春/夏/秋/冬 |
| 3 | **甲（Jia）** | 障碍等级：初甲/再甲/三甲 |
| 4 | **元（Yuan）** | 上下文新鲜度：新/陈 |
| 5 | **峙（Zhi）** | 推力 vs 阻力评估 |
| 6 | **决（Jue）** | 输出 7 种方位决策之一 |

| 方位决策 | 含义 |
|----------|------|
| **Continue** | 继续当前路径 |
| **PushThrough** | 硬推——增强偏置强度 |
| **NavigateAround** | 绕行——改变问题切入角度 |
| **Decompose** | 分解——将当前问题拆分子任务 |
| **Escalate** | 升级——请求外部帮助或切换策略 |
| **Abort** | 终止当前任务 |
| **WaitGather** | 等待——收集更多上下文再决策 |

### 第三引擎：周易（ZhouVM）— 认知姿态

**代码已实现，尚未接入主流水线。**

周易引擎决定模型用**什么认知姿态**去处理当前任务。通过 8 卦格栅 + 五行生克权重矩阵控制温度和行为倾向：

| 卦象 | 元素 | 姿态 | 温度 | 适用场景 |
|:---:|:---:|:-----|:---:|---------|
| **乾** | 金 | 创造 | 1.2 | 头脑风暴、创意生成 |
| **兑** | 金 | 表达 | 0.9 | 沟通解释、教学输出 |
| **离** | 火 | 明照 | 0.5 | 深度分析、焦点审查 |
| **震** | 木 | 启动 | 1.0 | 新任务初始化 |
| **巽** | 风 | 渗透 | 0.7 | 渐进推理、细节展开 |
| **坎** | 水 | 破局 | 1.1 | 跳出思维定势 |
| **艮** | 山 | 止定 | 0.3 | 精确聚焦、严格收敛 |
| **坤** | 土 | 承载 | 0.6 | 默认稳定状态 |

格栅状态转移遵循五行生克规则（金生水、水生木、木生火、火生土、土生金；金克木、木克土、土克水、水克火、火克金），由 8×8 Markov 权重矩阵驱动。

## 象语言：三套算子的统一约束语言

**象语言不是归藏的语法糖。它是三套独立算子体系的统一约束语言。**

三套引擎共享同一套底层类型系统（定义在 `xiang-core` 中）：

| 共享类型 | 作用 | 被哪些引擎使用 |
|---------|------|--------------|
| **Gua(u8)** | 6 位卦象状态（0-63） | 全部三引擎 |
| **八气算子** | 生/动/归/长/育/杀/止/藏 | CangVM 执行，ShanVM 输出策略，ZhouVM 调整姿态 |
| **FangWei** | 7 种方位决策 | ShanVM 产出，CangVM 消费 |
| **Bagua** | 8 卦 + 生克权重矩阵 | ZhouVM 核心，CangVM 读取温度 |
| **CangSea** | 64×64 Hebbian 经验矩阵 + 语义存储 | 归藏沉淀，连山/周易消费 |

这种共享类型体系意味着：

1. **单条训练数据包含三层标签**：归藏的算子序列 + 偏离度、连山的方位决策 + 障碍等级、周易的卦象姿态 + 生克权重
2. **云端评判可以精确到每一层**：不仅评判"偏离度是否合理"，还评判"这个障碍下选择绕行是否合理"、"当前用震卦姿态是否合适"
3. **三层引擎各自积累经验**：归藏的藏海、连山的策略格栅、周易的转移权重，都可以从成功/失败频率中自调整

象语言语法示例：

```
定义 思维向导:
    卦 焦点状态 = 111111
    生
    动
    归
    若 偏离度 > 0.7:
        杀 110
        藏 恶
    若 偏离度 < 0.3:
        藏 善
    否则:
        止 101101
        藏 善
```

## 三层协同闭环

```
用户请求
    │
    ▼
┌─────────────────────┐
│  周易 (ZhouVM)       │  ←─ 选择初始认知姿态（默认坤）
│  设定温度 / 行为倾向  │
└─────────┬───────────┘
          │ 卦象姿态
          ▼
┌─────────────────────┐
│  归藏 (CangVM)       │  ←─ 启动 8 算子周天
│  生→动→长→育...      │
│                      │
│  每步执行流程：        │
│  1. LLM 生成算子输出   │
│  2. 阴仪检查格式 + 偏离度 │
│  3. 偏离度偏高？⟶ 连山 │
│  4. judge() 决策      │
└─────────┬───────────┘
          │ 偏离度持续偏高 / 多轮重试
          ▼
┌─────────────────────┐
│  连山 (ShanVM)       │  ←─ 障碍导航激活
│  艮→气→甲→元→峙→决  │
│  输出 7 种方位决策    │
└─────────┬───────────┘
          │ 策略建议（绕行 / 分解 / 升级...）
          ▼
┌─────────────────────┐
│  归藏 (CangVM)       │  ←─ 执行策略建议
│  调整算子 / 重试策略  │
└─────────┬───────────┘
          │ 此轮结束
          ▼
┌─────────────────────┐
│  藏海 (CangSea)      │  ←─ 沉淀经验
│  记录：              │
│  · 算子序列 + 偏离度  │
│  · 连山决策 + 障碍等级 │
│  · 周易姿态 + 生克权重 │
│  Hebbian 加权 / 衰减  │
└─────────────────────┘
          │ 经验回流
          ▼
┌─────────────────────┐
│  云端评判             │  ←─ 外部质量评估
│  · 偏离度合理吗？     │
│  · 连山策略对吗？     │
│  · 周易姿态合适吗？   │
│  反馈回三层引擎参数调整 │
└─────────────────────┘
```

## 自举进化飞轮

三易统一后，飞轮变成**四维同步进化**：

```
                    ┌──────────────────────┐
                    │     原始模型          │
                    │  注意力不稳 / 无策略  │
                    │  单一认知姿态         │
                    └──────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
                    │   三易约束引擎         │
                    │                      │
                    │  周易：选择认知姿态     │
                    │  归藏：执行周天        │
                    │  连山：障碍导航        │
                    └──────────┬───────────┘
                               │ 高维标注数据
                    ┌──────────▼───────────┐
                    │   藏海（训练数据池）    │
                    │                      │
                    │  每条数据包含：        │
                    │  · 算子序列 + 偏离度   │
                    │  · 连山方位决策 + 障碍 │
                    │  · 周易卦象 + 生克权重 │
                    │  · Hebbian 复用权重   │
                    │  · 云端评判结果       │
                    └──────────┬───────────┘
                               │ LoRA 微调
                    ┌──────────▼───────────┐
                    │   进化后的模型        │
                    │                      │
                    │  · 注意力更稳定       │
                    │  · 遇障碍知策略       │
                    │  · 能切换认知姿态     │
                    │  · 产数据质量更高     │
                    └──────────┬───────────┘
                               │
                               ▼
                    ┌──────────────────────┐
                    │  回到第1层，起点更高   │
                    └──────────────────────┘
```

### 四维同步进化

| 维度 | 进化内容 | 数据来源 |
|------|---------|---------|
| **归藏** | 藏海经验积累，偏离判断越来越准 | Hebbian 权重 + 语义存储 |
| **连山** | 策略格栅积累"失败模式→成功策略"映射 | 方位决策 + 执行结果 |
| **周易** | 格栅状态转移权重根据成功频率自调整 | 姿态选择 + 任务完成度 |
| **模型本身** | LoRA 微调，内化八气算子，生成质量提升 | 藏海筛选数据 |

## 冷启动策略

三易初期的路由完全基于规则，不需要训练：

| 引擎 | 初期策略 |
|------|---------|
| **周易** | 简单任务 → 坤卦（稳定），复杂任务 → 乾卦（创造），高精度任务 → 离卦（明照） |
| **连山** | 初甲硬推，再甲绕行，三甲分解。规则固定，不需要学习 |
| **归藏** | 偏离度计算纯数学，正则检查纯形式化，都不需要训练 |

随着数据积累，三层的参数逐步从纯规则过渡到经验驱动。

## 硬件需求

| 规模 | 模型 | VRAM | 上下文 |
|------|------|------|--------|
| 最轻量 | Qwen2.5-0.5B | ~1-2 GB | 32K |
| 推荐 | Qwen2.5-1.5B | ~2-3 GB | 32K-64K |
| 当前测试 | Qwen3.5-4B | ~5 GB | 64K |

### 硬件限制说明

本项目在 **AMD RX 6650 XT (8GB VRAM)** 上开发与测试。路线A（推理时外部约束）已验证可行并接入真实模型。但路线B（LoRA 微调内化约束原语）在当前硬件上受阻：

- 4B QLoRA 微调需 ~7-8GB VRAM，但 **AMD Windows 无可用训练工具链**（bitsandbytes 仅 CUDA）
- 推荐解除路径：云端 GPU（Google Colab / AutoDL）或硬件升级至 ≥16GB VRAM

详见 [ARCHITECTURE.md](./ARCHITECTURE.md#九硬件约束与当前瓶颈)。

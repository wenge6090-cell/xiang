# 象 (Xiang) — 为不可控的生成，装上可编程的控制系统

> **不是让模型更聪明，而是让它拥有结构化的意识校准、策略选择、姿态调整能力。**
>
> 一个基于形式化认知约束语言（象语言）的**推理时模型控制系统**。它不训练模型变聪明，而是用确定性状态机，为概率性的 LLM 生成过程装上方向盘、油门和刹车。

## 它是什么

**象** 是一个推理时认知约束框架。它将三套独立的易经算子体系（归藏/连山/周易）统一为一门名为 **象语言 (XiangLang)** 的约束语言，实现对 LLM 生成过程的程序化干预——不靠 prompt，靠确定性代码。

- **归藏** 是执行器，像心跳一样维持思维周期，实时检测偏离
- **连山** 是策略师，遇到障碍时从 7 种策略中导航出最优路径
- **周易** 是姿态器，为不同任务动态调节模型的"认知温度"和风格
- **藏海** 是记忆体，记录成功与失败，驱动系统自我进化

这不是推理增强工具、上下文管理器或提示词工程。这是一个具备初步元认知能力的、可以自我进化的小模型 Agent 框架。

## 为什么需要它

当前主流的 Agent 框架（如 LangGraph）能编排任务，但解决不了模型**生成过程不可控**的根本问题：

- **没有过程约束**：模型会偏离目标、陷入死循环或格式错误
- **缺乏策略应变**：遇到障碍只会"硬推"，不懂"绕行"或"分解"
- **认知姿态单一**：所有任务都用同一种风格，无法在"创造"与"审慎"间切换
- **经验无法积累**：每次重启都是一张白纸，重复踩进同一个坑

**象** 就是为解决这些问题而生的。它用一套完整的认知控制闭环，让一个 4B 的小模型也能表现出稳定、可靠、有策略的复杂任务处理能力。

## 控制闭环：检测 → 干预 → 学习

当模型生成偏离用户意图时，系统经历一个完整的负反馈闭环：

```
用户输入
    │
    ▼
┌─────────────────────────────────────────────────────┐
│                   周易 (ZhouVM)                       │
│              根据任务类型设定初始认知姿态               │
│         乾(创造) / 坤(稳定) / 离(分析) / ...          │
└─────────────────────────┬───────────────────────────┘
                          │ 温度 + 行为倾向
                          ▼
┌─────────────────────────────────────────────────────┐
│                   归藏 (CangVM)                       │
│              启动 8 算子周天循环                       │
│                                                       │
│  生→动→长→育  每步:                                   │
│    │            ├─ LLM 生成当前算子输出                │
│    │            ├─ 阴仪正则校验 ─── 格式不对？──→ 回滚  │
│    │            ├─ 偏离度计算（Hamming 距离 / 6）       │
│    │            └─ judge() 决策: PASS / ROLLBACK / ... │
│    │                                                   │
│    ▼  偏离度持续偏高 / 多轮重试？                      │
│   [是]                                                 │
└───────────┬───────────────────────────────────────────┘
            │ 障碍信号
            ▼
┌─────────────────────────────────────────────────────┐
│                   连山 (ShanVM)                       │
│              6 步障碍检测 → 7 种方位决策               │
│                                                       │
│  艮(阈值) → 气(阶段) → 甲(等级) → 元(新鲜度)          │
│  → 峙(力比) → 决(输出): 硬推/绕行/分解/升级/...       │
└─────────────────────────┬───────────────────────────┘
                          │ 策略建议
                          ▼
              ┌───────────────────────┐
              │   归藏执行新策略       │
              │   调整算子 / 重试      │
              └───────────┬───────────┘
                          │ 本轮结束
                          ▼
┌─────────────────────────────────────────────────────┐
│                   藏海 (CangSea)                      │
│              经验沉淀 + 回流                           │
│                                                       │
│  记录：算子序列 + 偏离度 + 连山决策 + 周易姿态         │
│  Hebbian 加权：成功经验 ↑  /  失败模式 ↓              │
│  回流 → 下一次归藏的偏离判断更准                       │
│  回流 → 连山的策略格栅积累"失败→成功"映射              │
│  回流 → 周易的转移权重根据成功率自调整                 │
└─────────────────────────────────────────────────────┘
```

这个闭环的四层对应四个核心模块——以下逐一展开。

## 象语言：三套算子的统一约束语言

**象语言不是归藏的语法糖。它是三套独立算子体系的统一约束语言。**

三套引擎共享同一套底层类型系统（定义在 `xiang-core` 中）：

| 共享类型 | 作用 | 被哪些引擎使用 |
|---------|------|--------------|
| **Gua(u8)** | 6 位卦象状态（0-63） | 全部三引擎 |
| **八气算子** | 生/动/归/长/育/杀/止/藏 | CangVM 执行，ShanVM 输出策略，ZhouVM 调整姿态 |
| **FangWei** | 7 种方位决策 | ShanVM 产出，CangVM 消费 |
| **Bagua** | 8 卦 + 生克权重矩阵 | ZhouVM 核心，CangVM 读取温度 |
| **CangSea** | 64×64 Hebbian 经验矩阵 + 语义存储 | 归藏沉淀，连山/周易消费 |

这种共享类型体系意味着：

1. **单条训练数据包含三层标签**：归藏的算子序列 + 偏离度、连山的方位决策 + 障碍等级、周易的卦象姿态 + 生克权重
2. **验证可以精确到每一层**：不仅评判"偏离度是否合理"，还评判"这个障碍下选择绕行是否合理"、"当前用震卦姿态是否合适"
3. **三层引擎各自积累经验**：归藏的藏海、连山的策略格栅、周易的转移权重，都可以从成功/失败频率中自调整

象语言语法示例：

```
定义 思维向导:
    卦 焦点状态 = 111111
    生
    动
    归
    若 偏离度 > 0.7:
        杀 110
        藏 恶
    若 偏离度 < 0.3:
        藏 善
    否则:
        止 101101
        藏 善
```

### 核心瓶颈：求助

**路线 B（LoRA 微调内化约束原语）在当前硬件上受阻。**

4B QLoRA 微调需要约 7-8GB VRAM，但 AMD Windows 平台缺少可用的训练工具链（bitsandbytes 仅 CUDA）。当前实验全部在 RX 6650 XT（8GB）上完成，这暴露了路线 A 外部约束的天花板——Logit-bias 只能"堵"不能"教"——也指明了路线 B 的必要性。

**我们在寻找有 NVIDIA GPU 或熟悉云端微调的开发者，共同完成路线 B。** 具体需要：构建 QLoRA 微调脚本、实现控制原语 token（14 个 Unicode 私有区 token）的词表扩展、验证内化约束在真实模型上的效果。作为回报，贡献者将成为项目核心开发者。

## 自举进化飞轮

三易统一后，飞轮四维同步进化：

| 维度 | 进化内容 | 数据来源 |
|------|---------|---------|
| **归藏** | 藏海经验积累，偏离判断越来越准 | Hebbian 权重 + 语义存储 |
| **连山** | 策略格栅积累"失败模式→成功策略"映射 | 方位决策 + 执行结果 |
| **周易** | 格栅状态转移权重根据成功频率自调整 | 姿态选择 + 任务完成度 |
| **模型本身** | LoRA 微调，内化八气算子，生成质量提升 | 藏海筛选数据 |

初期完全基于规则，不需要训练：简单任务用坤卦（稳定），复杂任务用乾卦（创造），高精度用离卦（分析）；连山初甲硬推、再甲绕行、三甲分解——规则固定，零学习成本。随着数据积累，三层参数逐步从纯规则过渡到经验驱动。

## 和现有方案的关系

LangGraph、AutoGen 做的是任务编排——约束在「流程」层。Guidance、LMQL 做的是语法约束——约束在「形式」层。STaR、ReST 做的是自训练——约束在「训练」层。蒸馏是一次性的知识迁移，不形成循环。

**象做的事不在这些层。** 它在「推理时认知状态」层——不编排任务、不限制语法、不修改权重，而是持续跟踪模型是否偏离了用户的初始意图，并在偏离发生时从三个维度（执行、策略、姿态）协同干预，把每次干预的结果沉淀为可回流的经验。

这不是替代，而是另一个维度上的补充。打个比方：LangGraph 是导航系统规划了路线，Guidance 是交规限制了行驶方式，象是你车上的偏离预警——不告诉你往哪开，但在你压线的时候打方向盘。

### 你是哪种角色？

**想快速体验效果的开发者**

```bash
git clone <repo-url> && cd xing && start_all.bat
```

5 分钟内用 4B 模型跑通 demo——聊天界面里能看到「裸奔输出」和「三易受控输出」的对比。没有 GPU？用 HttpBackend 对接远程 llama-server 也行。

**想贡献垂直领域知识的专家（不需要你会写代码）**

读这篇：[《如何用象语言定义你行业的规则》](./specs/04-象语言规范.md)。为 L1-L3 知识文件贡献实体和规则——这是「垂直领域知识图谱」护城河的起点。你只需要描述你领域的约束逻辑，剩下的由引擎执行。

**想研究控制理论的学者**

我们定义了「诚实验证」的形式化框架和「多维偏离向量」，但当前算法有已知不足。详见 [specs/05-三易算法内核.md](./specs/05-三易算法内核.md)。一个清晰的、可被挑战的开放性问题，比一个完美的工程更有吸引力。
